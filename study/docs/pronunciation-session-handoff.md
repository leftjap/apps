# 발음 음차·채점 세션 핸드오프 (2026-08-31)

새 세션은 이 파일만 읽으면 이어서 작업할 수 있다. 이 세션의 실측 스크립트는 세션 전용
스크래치패드에 있어 소멸한다 — 재현 절차는 [lesson-explanation-guide-en.md](./lesson-explanation-guide-en.md)
§7 의 재현 블록과 PA 절에 남겼고, Azure 접근 경로는 auto memory `study-azure-speech-local-probe` 에 있다.

## 이 세션에서 확정된 사실 (전부 실측 근거)

1. **채점 버그 (사용자 지적)**: Azure PA 는 ReferenceText 의 사전 발음에 음소를 정렬해
   채점하므로, 축약(모음이 schwa 로 무너져 음소가 사라지는 발화)일수록 깎였다.
   "What do you mean" 또박또박 93.0 vs 축약(whaddaya) 86.7 (en-US 3보이스).
   what·mean 은 97 유지, do(→80)·you(→66) 만 하락 — 앱이 실제 발음을 가르쳐 놓고
   그대로 하면 벌을 주는 구조였다. → **수정 완료** (아래 커밋 2).

2. **guide-en §7 '연음 경계 재분절 의무'는 근거가 반증됐다**: §7 표의 정본 예시 6쌍을
   그 문서의 실측 절차(ko-KR TTS 음차 → 영어 STT)로 ko-KR 9화자 재현 →
   개선 0 · 후퇴 4 · 동률 2. 채택 근거(캐뉴 푸리론 5/5 vs 4/5, n=5)는 9화자에서 8/9 동률.
   core100 시드에 규칙을 전면 적용한 A/B 도 같은 방향 (정확일치 38/108 → 30/108).
   → 전면 재음차와 게이트 차단 승격을 철회하고 §7 에 "재검토 대기" 기록.

3. **재음절화 발음 자체는 채점 무감점**: that again→[ðæɾəɡɛn]·missed it→[ˈmɪstɪt] 등
   음소를 잃지 않는 연음은 PA 점수가 동률이거나 오른다. 깎이는 것은 강한 축약뿐.
   레퍼런스를 축약형으로 '교체'하면 또박또박 발화가 50.0 으로 무너진다(단어 점수 3).

## 남은 작업 (즉시 실행 가능)

1. **시드 수정분 DB 반영** — `seeds/en-core100-2026-08-26.json` 은 repo 만 갱신됐고
   Supabase 에는 2026-08-26 업로드본이 그대로다. `study-seed-supabase.yml` 워크플로를
   재실행해야 앱 화면에 반영된다 (id 기준 upsert). 절차는 [seeds/README.md](../seeds/README.md).
   ⚠ DB 변경이므로 사용자 확인 후 실행. `dry_run=true` 먼저. user_id 는 원 업로드와
   같은 계정이어야 한다 (Supabase Dashboard → Auth 에서 확인).
2. **배포 확인** — push 는 했으나 `pnpm build`·`pnpm preview`·실기기(iPhone Safari)
   확인은 하지 않았다. 채점 수정은 speech.js 클라이언트 코드라 배포돼야 실기기에 반영된다.
3. (선택) **실기기 스모크** — 짧은 드릴("What do you mean" 등)을 흘려 발음해 점수가
   80대에서 90대로 오르는지 체감 확인.

## 사용자 결정 대기 (새 세션에서 물어볼 것)

1. **§7 재분절 의무의 처분** — 유지 / 완화 / 폐기. 코퍼스 5,000여 건에 영향.
   - 권장 = **폐기**: 두 실측(STT 인식률·PA 채점)이 같은 방향. 연음은 `phonemes`·`tips`
     설명으로 가르치고 음차는 단어 경계를 지키는 쪽이 낫다. 시드의 해설 필드가 이미
     그렇게 하고 있다 (예: "'익스플레인 잇'이 붙어 '익스플레이닛'처럼 들린다").
   - 폐기 결정 시 후속: §7 표·문구 개정, validate-seed 경고 문구 갱신(또는 경고 제거),
     기존 코퍼스는 손대지 않음(재음차가 오히려 후퇴임이 실측됨).
2. **CONTRACTIONS 확장 여부** — `understood you` 류는 Azure 사전에 축약 철자가 없어
   여전히 깎인다. 새 항목은 반드시 실측 확인 후 추가 (없는 철자를 넣으면 그 요청이
   통째로 저점이 되어 해롭다). 확장 시 memory 의 실측 경로 사용.
