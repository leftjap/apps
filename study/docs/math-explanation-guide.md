# 수학 해설 작성 가이드 — 친절·자세·비유 (정본)

> `study-math-content` 스킬·생성기·개념 카드·응용 해설이 따르는 **설명 품질 정본**.
> curriculum.md(무엇을 가르치나)와 짝 — 본 문서는 **어떻게 설명하나**.

## 0. 왜 이 가이드 (배경)

기존 해설은 결과만 단정했다(terse). 예: "홀수를 ㄱ자로 둘러 보면 정사각형 → 그래서 n²." 입문자는 *왜 ㄱ자인지·왜 홀수인지·왜 n²인지*에서 전부 막힌다. 거기에 같은 문구·풀이를 여러 곳에 복붙·재활용했다 — 이건 **작업 축소**다.

**원칙: 매 콘텐츠를 그 내용 고유로, 입문자가 혼자 읽고 깨달을 만큼 충분히 자세하고 친절하게.** 길어져도 좋다. 이해 > 간결.

## 1. 7원칙 (모든 해설 강제)

1. **도약 금지.** 결론과 결론 사이 모든 단계를 메운다. "그래서 n²" 같이 건너뛰지 않는다 — 그 "그래서"를 풀어 쓴다.
2. **매 단계 "왜?" 선제 답변.** 입문자가 그 줄에서 떠올릴 질문("왜 그렇지?")을 미리 답한다.
3. **비유 의무.** 추상 단계마다 일상 비유 1개 이상(양파 껍질·피자·계단·물탱크·복사기·지도…). 비유는 개념의 *구조*와 실제로 맞아야 한다(장식용 금지).
4. **작은 수로 먼저, 그다음 일반화.** 1·2·3 구체로 보여주고 → n으로 일반화. 추상부터 시작하지 않는다.
5. **친절한 어조.** 경어체("~해요/~예요"), 격려. 위협적 기호·전문용어 남발 금지. 용어는 처음 쓸 때 풀어준다.
6. **한 문단 한 생각.** 한 번에 하나만. 빽빽한 한 문단에 3개념 욱여넣지 않는다.
7. **고유성(반-재활용).** 복붙·돌려쓰기 금지. 같은 비유를 두 개념에 우려먹지 않는다. 각 문제 수치·상황에 맞춰 매번 새로 쓴다.

## 2. 안티패턴 (하지 말 것)

- 결과 단정: "~이므로 ~이다" 로 끝 (과정 생략).
- 비유 0: 순수 기호·공식만.
- 추상 선행: n·변수부터 던지고 구체 예 없음.
- 복붙: 다른 개념/문제와 같은 example·think 문구.
- 용어 무설명: 제곱근·기댓값 등을 풀이 없이 사용.

## 3. 개념 카드 `body` — 단계 빌드

목표: 공식 암기가 아니라 **보고 깨닫게**. 3단 구성, 비유로 관통:

- **(a) 구체적 출발** — 작은 수나 그림 한 조각으로 시작(점 1개, 변 3·4, 반지름 1…).
- **(b) 한 걸음씩 키우며 패턴 발견** — 각 걸음마다 *왜 그렇게 되는지* 답한다. 1→2→3 으로 늘리며 규칙을 눈에 보이게.
- **(c) 일반화** — 그래서 n 일 때 왜 그 공식이 되는지. (a)(b)에서 쌓은 직관으로 자연스럽게.

`body` 는 2문단으로 부족하면 3~4문단 써도 된다. 각 문단 한 생각.

`worked` 는 body 의 일반식을 작은 수 하나로 *손으로* 굴려 보이는 확인(계산 과정 노출).

## 4. 5부 (개념 카드 전체)

| 필드 | 역할 | 풍부화 기준 |
|---|---|---|
| `body`(개념) | §3 단계 빌드 | 비유 + why + 작은수→일반화 |
| `worked` | 예시 산술 | 한 케이스 손계산 |
| `background`(배경) | 유래·동기 | 누가/왜 만들었나, 역사·실제 문제(가우스·이집트 측량·아르키메데스 등 구체) |
| `value`(왜 배울 가치) | 무엇으로 이어지나 | 이후 수학·다른 개념과의 연결 + 사고 도구로서의 값 |
| `thinking`(길러지는 사고) | *사고법* 명시 | 환원·보존·차원·간접측정 등 **이름** + 그 사고가 일상서 쓰이는 장면 |
| `realLife`(실생활) | 구체 사례 | **3개 이상**, 손에 잡히는 장면(추상 "여러 곳" 금지) |

각 필드 1~3문장. background 는 가능하면 실제 일화/유래로 흥미를 건다.

## 5. 응용 `solution` (6필드)

| 필드 | 역할 | 풍부화 기준 |
|---|---|---|
| `core` | 한 줄 원리/공식 | 짧게 |
| `idea` | **어떻게 생각하면 풀리나** | 가장 중요 — 비유·그림으로 풀이의 *발상*을 푼다. 단순 대입 X |
| `steps` | 계산 단계 | 각 줄이 무엇을 하는지 보이게 |
| `refresh` | 쓰인 기초 환기 | 제곱·평균·÷2 등 |
| `example` | 이 수치가 **현실 어디서** | 구체 장면(문제마다 고유) |
| `think` | 기르는 사고 한 줄 | 문제마다 고유 |

`idea`·`example`·`think` 는 **문제별 고유**. 같은 개념의 다른 문제와 복붙 금지.

## 6. 도형(figure) 의무 — 말로 때우지 말 것 (최우선)

> 사용자 지적(2026-05-24): "이미지 띡 하나 넣고 말로 무마. 해설 과정에 도형으로 설명하는 게 하나도 없다." → **그림이 빠진 해설은 미달.** 수학 사고력은 *보고 깨닫는* 게 본질이라 도형이 장식이 아니라 본문이다.

**규칙 (개념·응용 공통):**

1. **개념 figure 는 "변형"을 단계로 그린다.** 결과 도형 하나(예: 완성된 정사각형)만 띡 넣지 않는다. 1→2→3 으로 *자라는/쪼개지는/재배열되는* 과정을 패널·점선·색으로 보인다(예: `oddSquareSteps` 1·4·9·16 패널, `staircaseToRect` 계단 두 벌→직사각형, `circleToRect` 부채꼴→직사각형).
2. **개념 `body` 는 그 figure 를 손으로 짚으며 쓴다.** "그림에서 ㄱ자 한 겹이 +3 으로 보이죠?" 처럼 글이 그림의 어느 부분을 가리키는지 연동한다. 그림 따로·글 따로 금지.
3. **응용은 `solution.figure` 가 의무다.** 모든 응용 해설에 *풀이 발상*을 시각화하는 도형 1개. 단순 결과가 아니라 **방법**(직사각형의 절반·자르고 붙이기·평균 폭·역방향 √·지름÷2)을 그린다. 프롬프트 도형(문제 그림)과 별개로, 해설 패널 맨 위에 발상 그림을 둔다.
4. **파라메트릭 헬퍼로만.** `src/data/math/figures.js` 헬퍼에 의미 파라미터(라벨과 같은 숫자) 넣어 좌표를 *계산*. 손코딩 raw SVG·비율 불일치 금지. 비율=라벨은 **단위테스트로 자동 검증**(`figures.test.js`). 상세 규약 = `docs/math-curriculum.md` §도형 규약.

**안티패턴 (= 현재 콘텐츠의 실패):**
- 해설(solution)에 figure 0개 — idea 가 "직사각형 10×6의 절반" 한 줄로 끝(단순 대입). → **방법을 그림으로 보이고**, idea 로 그 그림을 풀어 쓴다.
- 개념 figure 가 결과만(완성 도형) — 변형 과정 없음.
- legend 로 설명을 때움 — legend 는 한 줄 캡션일 뿐, 본문/해설이 그림을 직접 짚어야.

## 7. Good vs Bad — 홀수합(odd) 비교

**Bad(기존, terse):**
> 1, 3, 5, 7… 홀수를 ㄱ자로 한 겹씩 둘러 보면 정사각형이 채워져요.
> 그래서 연속한 홀수의 합은 항상 제곱수 — 홀수 n개의 합 = n².

→ 왜 ㄱ자? 왜 더하는 게 늘 홀수? 왜 n²? 셋 다 생략. 그림 없으면 못 깨달음.

**Good(목표):**
> 점 하나에서 시작해요(●, 1개). 이걸 ㄱ자(기역자) 모양으로 감싸 볼게요 — 오른쪽 한 점, 위 한 점, 모서리 한 점, 그렇게 3개를 더하면 2×2 정사각형(4개)이 됩니다.
> 한 번 더 ㄱ자로 감싸면 이번엔 5개가 붙어 3×3(9개)이 돼요. 마치 양파가 껍질을 한 겹씩 두르며 굵어지듯, 정사각형이 한 겹씩 자라죠.
> 감쌀 때마다 더해지는 점은 1 → 3 → 5 → 7 … 늘 홀수예요. 한 겹은 '한 줄 + 옆 줄 + 겹치는 모서리 1개'라, 짝수에 1을 더해 항상 홀수가 되거든요.
> 그러니 홀수를 n개 더한다는 건 ㄱ자를 n겹 둘렀다는 뜻 = 한 변이 n인 정사각형. 답은 n × n = n². 더하기를 '정사각형 채우기'로 바꿔 본 거예요.

→ 비유(양파), 작은 수(1→4→9), 매 단계 why(왜 홀수·왜 n²) 전부 메움.

## 8. 체크리스트 (작성 직후 — "친절·자세" 단정 전)

- [ ] 결론 사이 **도약 없음** (매 단계 why 메움)
- [ ] **비유 1개+** — 개념 *구조*와 일치(장식 아님)
- [ ] **작은 수 구체 예 → 일반화** (추상 선행 X)
- [ ] **경어체·친절·격려** / 용어 첫 등장 시 풀이
- [ ] 개념 5부·응용 6필드 각 역할 충족, `idea`·`example`·`think` **문제별 고유**
- [ ] `realLife` 구체 사례 **3개+**
- [ ] **재활용·복붙 없음** — 이 내용 고유로 새로 씀
- [ ] **개념 figure = 변형 과정**(결과만 ❌), `body` 가 그 그림을 짚어 서술
- [ ] **응용마다 `solution.figure`**(발상 시각화) — 해설에 그림 0개 ❌
- [ ] figure = **파라메트릭 헬퍼**(figures.js) 생성, 비율=라벨(단위테스트 통과)
- [ ] **입문자가 그림+이 글만으로 혼자 깨달을 수 있나?** (가장 중요 — 못 하면 부족)
