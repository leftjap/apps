### 사용 규칙

1. 작업 시작 전 위 매핑에서 **필수 섹션 번호를 모두 나열**하고 응답 시작 블록 `[적용 규칙]`에 기재.
2. 각 섹션을 `view_range`로 선택 로드. 전체 파일 스캔 금지.
3. 매핑에 없는 애매한 작업은 사용자에게 "어느 섹션을 봐야 하는지" 먼저 확인.
4. 스펙 수치·구조를 변경할 때는 해당 섹션 번호를 근거로 사유 명시.
5. UI 작업 시 `src/styles/paper.css` 의 `:root` 토큰을 반드시 먼저 로드한다.
   토큰 확인 없이 시안 작업 시작 금지.

## 4. 데이터 저장

### 로컬: IndexedDB + Dexie.js

```javascript
const db = new Dexie('gym_사용자해시');
db.version(1).stores({
  sessions: 'id, date, *tags',          // 운동 세션
  prs: '[exerciseId+type], exerciseId',  // PR 이력
  weights: 'date',                       // 체중 기록
  customExercises: 'id',                 // 커스텀 운동
  settings: 'key'                        // 사용자 설정
});
```

- `navigator.storage.persist()` 요청하여 영구 저장
- 사용자별 별도 DB → 멀티유저 완전 격리

### 클라우드: Supabase (무료 티어, Study 앱과 동일 프로젝트)

**테이블 구조** (`gym_` 접두사로 Study 테이블과 분리):

```sql
gym_sessions (
  id TEXT PRIMARY KEY,
  user_id UUID REFERENCES auth.users,
  date DATE NOT NULL,
  start_time BIGINT,
  end_time BIGINT,
  blocks JSONB,                 -- 운동 블록 배열 (block.type='single' 만 사용)
  tags TEXT[],                  -- 부위 ID 배열
  total_volume INTEGER,
  total_calories INTEGER,
  duration_min INTEGER,
  status TEXT DEFAULT 'active', -- 'active' | 'completed'
  created_at TIMESTAMPTZ DEFAULT now()
);

gym_prs (
  id TEXT PRIMARY KEY,          -- exerciseId + type
  user_id UUID REFERENCES auth.users,
  exercise_id TEXT NOT NULL,
  type TEXT DEFAULT 'e1rm',
  weight REAL,
  reps INTEGER,
  e1rm REAL,
  date DATE,
  session_id TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);

gym_weights (
  date DATE,
  user_id UUID REFERENCES auth.users,
  weight REAL,
  height INTEGER,
  PRIMARY KEY (date, user_id)
);

gym_custom_exercises (
  id TEXT PRIMARY KEY,
  user_id UUID REFERENCES auth.users,
  name TEXT,
  part TEXT,
  equipment TEXT,
  default_sets INTEGER,
  default_reps INTEGER,
  default_weight REAL,
  met REAL,
  created_at TIMESTAMPTZ DEFAULT now()
);

gym_user_settings (
  user_id UUID PRIMARY KEY REFERENCES auth.users,
  weekly_goal INTEGER DEFAULT 4,
  height INTEGER,
  birth_year INTEGER,
  goal_weight REAL DEFAULT 69,
  hidden_exercises TEXT[],
  exercise_order JSONB,
  exercise_part_override JSONB,
  updated_at TIMESTAMPTZ DEFAULT now()
);
```

**RLS 정책** (모든 gym_ 테이블에 동일 패턴):
```sql
ALTER TABLE gym_sessions ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users can only access own data"
  ON gym_sessions FOR ALL
  USING (auth.uid() = user_id);
-- 나머지 테이블도 동일
```

**동기화 전략**:
- IndexedDB가 주 저장소 (오프라인 동작 보장)
- 온라인 시 Supabase와 양방향 동기화
- 서버 우선 병합
- 안전장치: 50% 이상 세션 감소 시 업로드 차단, 진행 중 세션 보호
- 오프라인: 동기화 차단, 온라인 복귀 시 자동 재시도 (5초, 15초, 45초)
- IndexedDB 빈 상태에서 업로드 차단 (서버 데이터 삭제 방지)

## 6. 운동 세션

### 6-1. 세션 시작
- 홈에서 "운동 시작" 탭 → 빈 세션 생성
- **세션 시작 시각 = 첫 운동 종목을 선택하는 순간** (`Date.now()` 저장)
- 경과 시간 표시 시작
- 빈 세션 상태(종목 없음)에서는 타이머 시작 안 함

### 6-2. 운동 추가 (footer 끝 "+")
- footer nav 우측 끝 원형 버튼 (38×38). footer nav 항목들과 시각적으로 한 줄
- **스타일: ui §6 Secondary 버튼 분류 준수** — 투명 배경 + accent 30% 보더 + accent 텍스트. Primary(solid accent 배경)는 과장됨 (세션 내 "운동 추가" 는 빈도 낮은 액션)
- 탭 → 운동 선택 **바텀시트** (부위→종목 선택)
- 바텀시트는 DOM에 한 번 생성 후 transform으로만 제어 (언마운트 금지, §6-10 참조)

**구 스펙 (v1) `56×56 FAB + accent solid` 는 폐기** — footer nav 와 별도 floating 버튼이 모바일에서 메인 컨텐츠 가림. footer 내 Secondary 원형 버튼이 iPhone PWA 에 적합

```
[바텀시트]
├── 상단 좌: 부위 탭 (chip 가로 스크롤): 가슴 / 등 / 어깨 / 하체 / 팔 / 유산소
├── 해당 부위 종목 리스트 (관리에서 숨김 처리된 종목 미표시)
├── 종목 순서: 관리 화면의 드래그 순서 반영
└── 동작: 종목 탭 → 세션에 추가, 바텀시트 닫힘
```

- 검색 기능 없음
- 최근 운동 노출 없음
- 2탭 완료 (부위 선택 → 종목 선택)
- **불필요한 재렌더 금지**: 토글/탭 전환 시 바텀시트/DOM 재마운트 금지. class 토글 또는 transform만.

### 6-3. 운동 카드 — A 방식 (현재 세트 크게)

**핵심 원칙**: 화면에는 **현재 세트 하나만 크게**. 이전/미완료 세트는 작게 요약 표시. 현재 세트가 화면의 주인공.

**카드 구조 (현재 진행 중인 운동)**:

```
┌────────────────────────────────────┐
│  벤치프레스           ● ● ◉ ○ ○    │  ← 운동명 + 세트 dots-pill (우상단)
│  ▓▓▓▓▓░░░░░░░░                     │  ← 프로그레스바 (§6-7)
│                                    │
│  [peek]        현재 카드    [peek]  │  ← 좌우 peek 카드 (작게 가로 요약)
│   02            60 kg        04    │
│  60×12                      60×10  │
│   ✓             10 회               │
└────────────────────────────────────┘
```

**운동명 표기 규칙**:
- 운동명만 표시. 장비명 병기 금지 (`(바벨)` 같은 접미사 전부 제거). 장비 종류는 §11 데이터로 내부 관리만

**세트 네비게이션 (우상단 dots-pill)**:
- 현재 세트 인덱스를 작은 pill 안의 도트 시퀀스로 표현: `● ● ◉ ○ ○` (완료·현재·예비)
- 숫자 `3/5` 문자열 표기 금지. 도트 시각화가 위계 낮은 네비 정보에 적합

**입력 UI — 빈 공간 탭 증감 (± 버튼 없음)**:
- 숫자 좌측 빈 영역 탭 = 감소. 숫자 우측 빈 영역 탭 = 증가
- ± 기호 UI 일체 금지 (시각적 노이즈). 증감 피드백은 숫자 값 변화 + 150ms 미세 플래시만
- 숫자는 크게 (Poppins light, 72px 수준), text-strong
- 숫자 자체 탭 → 커스텀 숫자 키패드 바텀시트 (§6-3-2)
- 터치 영역 구분: 좌 30% = 감소 / 중앙 40% = 키패드 / 우 30% = 증가

**카드 위계 (뮤직앱 now-playing 언어)**:

- **현재 카드 "떠오름" — 회전 금지, 평행 이동만**: `translate(+4px, -16px)` (좌상단→우상단 방향 이동으로 비대칭). 기울기(rotate) 금지 — 숫자 가독성·정적 안정감 해침
- **accent-tinted halo shadow**: 단순 회색 shadow 말고 accent 색 필터 들어간 그림자 → 따뜻한 "빛" 느낌
  - `0 32px 64px -8px rgba(217,119,87,0.22)` (accent halo) + `0 48px 96px -16px rgba(55,45,30,0.22)` (그레이 깊이)
- **카드 배경 subtle gradient**: 단조로운 흰 박스 금지. `linear-gradient(165deg, surface 0%, surface 55%, bg-warm 100%)` 로 빛의 면
- **상단 accent glow line** (pseudo ::before): 양 끝 페이드 가운데 accent. 현재 카드에만. "active" 시그널
- **좌상단 비대칭 악센트** (pseudo ::after): 20px 짧은 accent 라인. 에디토리얼 악센트 (ui §1 Asymmetric)
- **카드 radius 는 토큰 `--r-xl` (20px)** 사용 (ui §4 준수). 임의값 금지
- **peek 카드 rotate 금지** (현재 카드와 동일 원칙). 수평 수직 상태로 유지
- **peek 높이는 현재 카드와 가깝게** (현재 520 / peek 480 수준, 차이 약 40px). 입체감 + 위계는 주로 "현재 카드의 떠오름(translate·halo shadow)" 과 "peek 의 translateY 가라앉음·opacity 하향" 으로 표현
- **mask-image 페이드 제거** — rotate 없이는 어중간해짐. peek 카드 자체 경계(bg-warm · r-md radius) 로 충분히 "다른 카드" 신호
- peek 카드: bg-warm 배경 + shadow 없음 + 폭 80px + `opacity 0.72` + `translateY(+8~12)`
- peek 내용은 **가로 한 줄 배치 한 줄씩 세로 나열**. 세로쓰기 (`writing-mode: vertical`) 일체 금지
- 지시문(예: "← 밀어서 완료") 금지. 제스처는 사용자가 암묵적으로 학습
- **stat-divider 1px 라인 금지** (ui §6 "여백으로 시각 분리 우선"). 중량/회수 사이는 충분한 gap(48px)으로만 구분

**숫자 위계 (과대 금지)**:
- 중량 primary 72px Poppins 200 · 회수 secondary 36px Poppins 300. 차등은 유지, 극단 금지
- 이유: 숫자가 80px+ 이면 카드 내부 좌/우 여백이 좁아져 "빈 공간 탭 증감" 의 hit area 가 줄어듦 (§6-3 입력 UI). 오탭 방지 위해 숫자 크기는 제한

**탭 영역 (빈 공간 증감)**:
- tap-zone 좌/우 각 40% 폭. 숫자 영역 중앙 20% 유지. 시각적 "여백" 이 클수록 사용자가 탭 가능 영역을 쉽게 인지

**증분**:
| 장비 | 증분 |
|------|-----|
| 바벨 | 5kg |
| 덤벨 | 2kg |
| 머신/케이블 | 5kg |
| 맨몸 | 중량 없음 (횟수만) |
| 횟수 | 1 |

### 6-3-1. 스와이프 인터랙션

> **유산소 예외 (2026-08-18, 확정 시안 7a)** — 유산소 카드에서 좌우 스와이프는 세트 완료가 아니라
> **지표 로테이션**(시간 → 거리 → 칼로리)이다. 완료/저장 버튼·스와이프 완료·롱프레스 확정 모두 없고,
> 보존은 `cardioEntered` + 종료/마감이 담당한다. 상세: `specs/2026-08-18-cardio-input-design.md`.

| 제스처 | 동작 |
|---|---|
| **좌측 스와이프 (←)** | 현재 세트 완료 + 값 저장. 다음 세트로 전환. iOS 햅틱 피드백. |
| **우측 스와이프 (→)** | 이전 세트로. 해당 세트 값 수정 가능 모드 진입. |
| 세로 스크롤 | 세션 전체 스크롤 (카드 간 이동) |

**세부 규칙**:
- 수평 스와이프 임계값: 60px 이상 수평 이동 시 트리거. 수직 이동이 크면 스크롤로 판정.
- 현재 세트 입력 영역은 `touch-action: pan-y` 적용 — 수직은 네이티브 스크롤, 수평은 JS로 감지
- 마지막 세트(5/5)에서 좌 스와이프 → 세트 6 추가 모드 (새 행이 현재 세트 자리로)
- 5세트가 기본, 사용자가 원하는 만큼 계속 추가 가능
- 완료한 세트가 없는 상태(세트 1)에서 우 스와이프 → 무시
- 완료 버튼 없음. 좌 스와이프가 유일한 완료 방식.

**지시문·힌트 금지**:
- 화면에 "← 밀어서 완료" 같은 각주·지시문 일체 표시 금지
- 스와이프는 사용자가 사용 초기 한두 번으로 학습. 온보딩 대체 수단 없음 (나 혼자 쓰는 앱 전제)

### 6-3-2. 커스텀 숫자 키패드

숫자 영역 탭 시 바텀시트로 올라옴.

```
┌──────────────────────────────┐
│         62.5 kg              │  ← 현재 입력값 (크게)
├──────────────────────────────┤
│    1      2      3           │
│    4      5      6           │
│    7      8      9           │
│    .      0      ⌫           │
│                              │
│    [     완료     ]          │
└──────────────────────────────┘
```

- OS 키패드 사용 안 함 (레이아웃 예측 가능성 위해 커스텀)
- 소수점 버튼 지원 (덤벨 2.5kg 등)
- `⌫` = 한 자리 지우기
- 완료 버튼 → 값 적용 + 바텀시트 내려감
- 배경 탭 또는 아래로 스와이프 → 취소

### 6-3-3. 프리셋 (이전 값 자동 표시)

**값 우선순위**:
1. 이전 세션의 같은 세트 번호 값 (있으면 이것 우선 — 지난 기록을 세트별 타깃으로 표시)
2. 이번 세션의 **직전 세트** 값
3. 운동 기본값 (`defaultWeight`)

**표시 방식**:
- 세트 진입 시 우선순위에 따른 값이 **placeholder 톤** (text-faint)으로 표시
- placeholder 상태에서 좌 스와이프 → 그 값 그대로 기록 (0탭)
- ± 또는 키패드로 수정 시 → 실제 값 모드로 전환 (text-strong 색상으로 진해짐)

**이전 기록 없는 운동**:
- 첫 세트: 운동 기본값(defaultWeight, defaultReps) placeholder
- 첫 세트 완료 → 다음 세트는 직전 세트 값 상속

**세트바 최고(e1RM) 슬롯은 프리셋을 대체하지 않음** (2026-07): 세트바 끝에 역대 최고(무게×횟수)를 별도 슬롯으로 **추가 병기**할 뿐, 위 프리셋 우선순위·고스트 미리보기는 그대로 직전 기준을 쓴다. 최고는 "보이는 자극", 프리셋은 "오늘 칠 현실값" — 역할이 다르다(§6-11, 무게 종목 한정·기록 없으면 미표시).

### 6-4. 운동 카드 (유산소) — 5필드 패널 (2026-08-10 재설계, 상세: specs/2026-08-10-treadmill-record-design.md)

```
┌─────────────────────────────────┐
│ 트레드밀                        │
│      ▁▂▂▄▄▆  최근 8회 (막대=분) │  ← 최신 오른쪽 끝·마지막 막대 crail·기록 3회 미만 생략
│  직전 15분 · 1.5km · 경사 3.4   │
│                                 │
│            2 0                  │  ← 시간(분) mono 88 — 주인공
│            1.5 km               │  ← 거리 mono 44
│   속도      경사      칼로리    │  ← 콘솔 계기판 배치 (라벨 위·값 아래)
│  6.0km/h   3.4%      81kcal     │
│        페이스 10:00/km          │  ← 자동 계산 (시간·거리 있을 시)
└─────────────────────────────────┘
```

- 5필드 전부 탭 → 커스텀 키패드. 속도·경사·칼로리는 bare 키패드(세그 없음·타이틀).
- **스와이프 완료 없음.** 입력 순간 세트가 터치됨(preset false) → 종료·마감·종목완료 어느
  경로로도 보존 보장 (cardioEntered = "preset 아님 + 값 있음" — "값>0" 술어는 상속 프리셋을
  확정해 유령 기록을 만들었다, 2026-08-06 이중 집계 사고).
- 미입력 필드는 직전 러닝 값이 고스트(ink4)로 표시·프리필 — 입력하면 잉크로 진해진다.
  고스트 출처는 이력(recentCardioRuns)이며 프리셋 세트에 유산소 값을 카피하지 않는다.
- 페이스: 시간÷거리 자동, 속도·경사 1dp 고정 표기. 세트 개념 없음. 1운동 = 1기록.
- 유산소 칼로리: 입력 kcal 우선, 미입력 시 MET 추정 fallback — 세션 총계에 근력 추정과 합산 (§7-3).
- **시작/종료 스톱워치 없음**: 사용자가 기기(트레드밀 등) 계기판 값(평균)을 운동 후 수기 입력
  (콘솔이 종료 3~5초 뒤 꺼지므로 사진 찍어 두고 전사하는 워크플로 전제)
- 세션 경과 시간 처리: 유산소 카드의 입력 시간이 세션 경과 시간을 넘지 않으면 문제 없음 (넘으면 사용자 오기). 세션 총 시간 계산은 `Date.now() - startTime` 그대로 사용.

### 6-6. 세션 헤더 (운동 시간만)

```
[홈]              · 18:42              [종료]
```

- **경과 시간만 표시**. 타임스탬프 기반 (`Date.now() - startTime`). 세션 시작은 첫 종목 선택 시점.
- 시간은 가운데 정렬. Poppins 300 · 28~32px · text-strong 으로 display 타이포 처리 (헤더 내 주인공).
- 러닝 중 좌측에 accent pulse dot (5px) 표시.
- 좌: 홈 아이콘 (ghost). 우: 종료 텍스트 버튼 (ghost).
- **볼륨 비교 제거** (v2.1, 2026-04-20). 이유: 세션 헤더는 "지금 얼마나 운동했나(시간)" 만으로 충분. 볼륨 비교는 운동별 프로그레스바(§6-7)에서 담당 → 중복·정보 밀도 과잉. 부위 태그도 동일 이유로 이미 제거됨.
- 꾹누르기 "종료" → 종료/삭제 팝업 (확인/취소)

### 6-7. 운동별 프로그레스바

현재 진행 중인 운동 카드 상단에 얇은 프로그레스바.

- 바 높이: 2px. 배경 `--border-light`, 진행 부분 `--accent`.
- 진행도: **이번 운동의 현재 누적 볼륨 / 직전 이 운동의 총 볼륨**
  - 분모는 **직전 세션 같은 종목의 총 볼륨(고정 기준)** — "오늘 계획"이 아님. (v2.2 수정: 이전엔 현재 세션 계획 볼륨을 분모로 써, 세트만 다 끝내면 직전 대비 못 미쳐도 100%가 되는 버그가 있었음.)
  - 직전 기록이 없으면(첫 세션) 오늘 계획 볼륨으로 폴백.
  - 분자가 분모를 넘으면 `%`는 100% 초과 표기(직전 돌파), 바 fill 은 100%에서 cap.
- 첫 번째 세트: 직전 값을 작은 레이블로 병기 ("직전: 600kg")
- 100% 도달 시 진행 부분 짧은 pulse — 직전 기록 갱신 신호. 추가 텍스트·아이콘·캐릭터 없음.
- **세트바 최고(e1RM) 슬롯은 이 바의 분모/타깃이 아님** (2026-07): 세트바 끝의 역대 최고(무게×횟수) 슬롯·막대 높이 = e1RM 강도(§6-3)는 "보이는 자극 마커"일 뿐, 진행바 분모는 여전히 **직전 세션 총 볼륨**으로 고정. 최고로 분모/프리셋(§6-3-3)/고스트 미리보기를 교체하지 않는다.
- **우상단 세션 볼륨** (v2.2): 카드 우상단의 `SET N/M` 숫자 문자열(§6-3 도트-pill 규칙상 원래 금지)을 제거하고 **세션 단위 볼륨**(오늘 누적 done 볼륨 / 직전 세션 `totalVolume`)으로 대체. 직전 세션 없으면 "오늘 누적kg"만. 운동별 바(§6-7)는 종목 단위, 우상단은 워크아웃 단위 → 줌 레벨이 달라 중복 아님. (세트 진행도는 도트-pill 이 담당.)

### 6-8. 운동 상태 (4가지)

| 상태 | 표시 |
|---|---|
| **진행 중 (현재)** | 카드 펼침. A 방식 풀 UI. 주인공. |
| **진행 중 (보류)** | 접힘. 헤더: 운동명 · N/M세트 진행중 (중간톤). 탭하면 현재로 복귀. |
| **완료** | 접힘. 헤더: 운동명 · N세트 ✓ (흐림). 탭하면 읽기 전용 펼침. |
| **예정** | 접힘. 헤더: 운동명 (예정) (아주 흐림). 탭하면 현재로 전환. |

**다른 운동 탭 = 이동, 완료 아님.** 현재 운동은 보류 상태로 유지. 완료는 명시적 액션(§6-9 꾹누르기)으로만.

**footer nav 시각 표현 규칙 (Typography-driven · ui §1):**
- **is-current**: pill/배경 박스 금지. accent 텍스트 색 + weight 600 + size 15px + 상단 accent 도트(4px) + 하단 accent underline(2px). 메인 카드와 시각 연결은 도트/underline으로만
- **is-done**: line-through 금지. sage ✓ 아이콘 prefix + text-muted 색
- **is-hold**: text-muted + 끝에 작은 "·N/M" 부가 (text-faint)
- **is-pending**: text-faint 그대로

### 6-9. 꾹누르기 (Long Press, 500ms)

**공통 동작**:
- 500ms 홀드 → iOS 햅틱 피드백 + 살짝 축소 애니메이션 (scale 0.98)
- 스크롤 시작 감지되면 꾹누르기 자동 취소 (실수 방지)
- 모든 파괴적 액션은 **선택 → 확인** 2단계
- 메뉴는 바텀시트로 노출

**대상별 메뉴**:
| 대상 | 메뉴 |
|---|---|
| 진행 중 운동 카드 | 완료 / 삭제 / 이동 |
| 완료된 운동 카드 | 수정 / 삭제 / 이동 |
| 예정된 운동 카드 | 삭제 / 이동 |
| 세트 행 (완료 또는 미완료) | 수정 / 삭제 |
| 세션 헤더 "종료" 버튼 | 종료 / 삭제 세션 (확인/취소) |

**이동 동작** (전체 접힘 모드):
1. 꾹누르기 → 액션 시트 "이동" 선택
2. 모든 운동 카드가 **일괄 접힘 크기로 축소** (부드러운 애니메이션)
3. 선택된 카드만 살짝 들린 상태 (shadow 승격, scale 1.02)
4. 드래그해서 원하는 위치로
5. 놓으면 → 카드 새 위치 안착 + 모든 카드가 원래 상태(펼침/접힘)로 복귀

### 6-10. 불필요한 재렌더/로드 방지

**원칙**: 바텀시트, 오버레이, 팝업은 DOM에 한 번 생성 후 언마운트 금지. transform/opacity로만 노출/숨김.

**금지**:
- 토글/탭 전환 시 상위 컴포넌트 key 변경으로 리렌더 트리거
- 바텀시트 열 때마다 DOM 재생성
- 운동 선택 시 종목 리스트 재요청/재렌더

**권장**:
- 바텀시트: `transform: translateY(100%)` → `translateY(0)` 슬라이드 업
- 모든 정적 데이터(운동 종목 리스트 등)는 앱 시작 시 한 번 로드 후 메모리 유지
- 세트 추가/수정은 해당 행만 업데이트 (전체 카드 리렌더 금지)

### 6-11. PR 감지

**PR 판정**:
- 세트 완료(좌 스와이프) 즉시
- Epley 공식: `중량 × (1 + 횟수/30)` → 추정 1RM
- 이전 최고 e1RM 초과 시 PR (엄격 초과, 동률은 PR 아님 — `evaluateSetPR`)

**PR 모먼트(축하) 트리거 = 역대 e1RM 신기록만**:
- 세트 커밋 시 팝(cardPrPop)·강햅틱·세그 글로우는 **역대 최고 e1RM 을 엄격 초과**할 때만 발화 (`prMoment = persistSetPR().isPR`).
- ~~직전 세션 동일 종목 최대 **무게** 초과~~ 는 폐기 (2026-07 버그 수정 — 역대 e1RM 미달인데 무게만 높으면 오발화하던 문제). `cardPrChip`(히어로 하단 "+Nkg" 넛지)은 별개 채널로 여전히 **직전 세션 대비** 표시 (progressive overload 넛지, KEEP).

**PR 알림**:
- 세트 카드 위에 **"PR"** 텍스트만 짧게 팝 (accent 색, Poppins 500)
- 위로 살짝 떠오르다 1초 내 페이드아웃
- 세트 행에는 accent 색 숫자로 영구 표시

**PR 저장**:
- 운동별: `{exerciseId, weight, reps, e1rm, date, sessionId}` 배열
- 세트 삭제/수정 시 자동 재계산

**삭제된 기능** (v1에서 있었지만 v2에서 제거):
- PR 힌트 ("60kg × 11회 이상이면 PR")
- PR 토스트 (캐릭터 + 크게 뜨는 알림)

- MET 기반: `(MET × 체중 × 시간(시) × 1.05)`
- 최신 체중 기록 사용 (미등록 시 70kg 기본)

## 8. 세션 지속성

### 타임스탬프 기반 경과 시간
- `setInterval` 카운팅 아님
- **세션 시작 시 `startTime = Date.now()` 저장** (첫 운동 종목 선택 시점)
- 화면 복귀(`visibilitychange`) 시 `Date.now() - startTime` 재계산
- 화면 꺼짐, 다른 앱 사용 중에도 정확한 경과 시간

### 자동 저장
- 30초마다 + `visibilitychange` 시 IndexedDB에 세션 상태 저장
- 세트 완료(좌 스와이프) 시마다 즉시 저장

### 세션 재개
- 앱 재진입 시 미완료 세션 감지 → 홈에 "진행 중" 카드 표시
- 세션은 명시적 "운동 종료" 또는 24시간 무활동 시에만 종료

## 10. 관리 화면

### 10-1. 부위별 운동 관리
- 6개 부위 탭
- 운동 리스트: 기본 + 커스텀 + 숨김(토글) 표시. 삭제한 운동은 미표시(영구 제거)
- 숨기기/보이기 토글 (숨긴 종목은 운동 선택에서 미표시, 관리 리스트엔 흐리게 유지 — 임시 비활성)
- 꾹누르기(500ms) → "삭제": 커스텀은 DB 행 삭제, 빌트인은 settings.deletedExercises 로 영속 삭제. 둘 다 목록·운동선택에서 영구 제거(임시로 끄려면 토글 사용)
  - 손가락 이동 → 인플레이스 드래그 정렬 (떼는 시점에 새 순서 영속)
- 커스텀 운동 추가: 이름, 부위, 장비, 기본 세트/횟수/중량
- 운동 부위 변경 가능

### 10-2. 체중 관리
- 현재 체중 입력 (탭 → 커스텀 숫자 키패드, 소수점 1자리)
- 목표 체중 설정 (기본 69kg)
- 추이 그래프: 체중 라인 + 7일 이동평균선 + 목표선(점선)
- 남은 감량량 + 예상 달성 시기 (월 1.5kg 기준)
- 체중 신기록(최저점) 달성 시 "PR" 팝 애니메이션 (§6-11과 동일 방식)
- 체중 기록 수정/삭제 가능

### 10-3. 프로필/설정
- 키 (cm), 생년월일
- 주간 목표 횟수 (기본 4)
- 동기화 상태 표시 (마지막 동기화 시간)

**삭제된 설정**: 휴식 타이머 관련 전체 (ON/OFF, 기본 시간).
