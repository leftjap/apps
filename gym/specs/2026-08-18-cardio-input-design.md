유산소(트레드밀) 입력 UI 개선 작업지시서

  확정 시안 7a · 2026-08-18 · leftjap/apps · gym

    구현 대상 — 두 코드베이스 모두

    1) PWA(기준 구현) src/features/session.js · src/styles/paper.css · mocks/session.html

    2) Swift 포팅 GymKit/Sources/GymViews/CardioPanel.swift · 로직은 GymCore/SessionLogic.swift

    SessionLogic.swift 헤더가 "PWA src/features/session.js 1:1 포팅"을 명시한다. PWA를 먼저 고치고 Swift를 맞춘다. 순수 로직(지표 전환 상태, 주간 집계)은 GymCore에 두고 뷰는 표시만 한다.

  1. 개요

  유산소 카드가 입력 필드만 나열된 형태여서 동기부여 요소가 없고, 다른 종목과 같은 스와이프 완료 제스처가 유산소의 다중 값 입력과 맞지 않는 문제를 해결한다. 입력 항목은 헬스장 트레드밀 콘솔이 제공하는 세 값(시간·거리·칼로리)으로 한정하고, 카드 상단에 주간 기록을 상시 노출한다.

  스와이프는 완료가 아니라 지표 로테이션으로 재정의한다. 좌우로 밀면 시간 → 거리 → 칼로리 순으로 넘어가고, 히어로 값·주간 캘린더 숫자·주간 합계·단위가 모두 해당 지표로 함께 전환된다.

  2. 화면 구성

  상단부터 순서대로 다섯 블록이며, 주간 캘린더 아래 세 블록(히어로 · 도트 · 요약)은 남는 높이를 space-evenly로 균등 분배한다(간격 약 52px).

        블록
        내용

      헤더	기존 유지. 우상단 세션 볼륨 비교(4,800 / 8,940kg + 링 54%)는 전 페이지 공통 요소이므로 삭제·생략 금지.

      주간 캘린더	월~일 7개 원(37px) + 요일 라벨. 원 안 숫자는 활성 지표의 값. 하단 우측에 주간 합계 + 단위.

      히어로	활성 지표 라벨 + mono 100px 값 + 단위. 316px 폭 셀 3개가 가로 트랙에 배치되고 활성 셀만 불투명도 1.

      진행 도트	3개. 활성 18×6px crail, 비활성 6×6px 회색. 기존 세트 dots-pill과 같은 언어.

      비활성 요약	나머지 두 지표의 라벨 + mono 28px 값. 탭하면 해당 지표로 즉시 전환.

      종목 레일	기존 유지. 다음 종목 이동은 레일이 담당한다.

  3. 시안

      그림 1. 시간 지표. 오늘(금) 32분 입력됨 → 원이 채워지고 합계 82분·4일.

      그림 2. 두 번 스와이프한 칼로리 지표. 오늘 미입력 → 원은 참조 스타일(85), 합계 309kcal·3일에서 제외.

        제스처
        동작

  5. 데이터 명세

    집계 범위 — 해당 종목만. 카드가 종목 단위이므로 트레드밀 카드의 캘린더·합계는 exerciseId == 'treadmill' 기록만 센다. 사이클·엘립티컬(equipment:'cardio')은 제외하며, 그 종목의 카드는 자신의 기록을 보여준다. 그 결과 홈 화면의 유산소 행(유산소 전 종목 합산)과 이 카드의 수치는 달라질 수 있다 — 의도된 것이고 버그가 아니다.

    주 기준 — 홈과 동일한 월~일(KST) 캘린더 주. GymHomeLogic.weeklyBalance와 같은 주 경계를 쓴다(집계 범위는 위 항목처럼 다름). 롤링 7일 금지.

    원 안 숫자의 출처 — 지난 요일은 그 날의 실제 기록값. 해당 지표 기록이 없는 날은 —. 분에서 거리·칼로리를 역산하지 않는다.

    미래 요일 — 지난주 같은 요일의 같은 지표 기록을 회색으로 표시한다(참조용). 이 값이 요청의 출발점인 "지난주 기록이 숫자로 남아 참조가 편하다"에 해당한다.

    오늘 · 미입력 — 히어로 고스트와 같은 원천(직전 러닝 값)을 표시하고, 원은 기록 스타일이 아닌 참조 스타일(투명 배경 + 연한 테두리·숫자)을 쓴다. 주간 합계·일수에서 제외한다.

    오늘 · 입력됨 — 원을 teal로 채우고 흰 숫자. 합계·일수에 포함.

    원의 형태는 지표와 무관 — 크기·색·채움 여부는 항상 시간 기준으로 결정하고, 스와이프 시 숫자만 바뀐다. 주간 리듬이라는 고정 좌표를 유지하기 위한 규칙이다.

    합계 단위 — 활성 지표에 따라 분 / km / kcal로 함께 바뀐다. 단위가 없으면 숫자만 바뀌어 무엇을 보는지 알 수 없다.

    값 보존 — 별도 확정 액션 없이 cardioEntered(preset 아님 + 값 있음)가 종료·마감 어느 경로로도 기록을 지킨다.

  5-1. 저장 계약 (기존 코드 그대로 사용)

        지표
        필드 · 저장 단위
        입력 → 저장 변환

      시간	duration · 초	화면·키패드는 분. max(0, round(분×60))

      거리	distance · km	소수 1자리로 반올림. 키패드 소수점 허용

      칼로리	calories · kcal	정수 반올림. 키패드 소수점 비활성

    쓰기는 applyCardio(set:field:value:)만 통한다(단위 변환·preset=false 처리 포함). 여기서 done을 세우지 않는다 — 즉시 done이면 블록이 완료 판정돼 히어로가 다음 종목으로 넘어간다.

    빈 공간 탭 증감도 같은 경로를 쓴다. 하한 0에서 더 감소시키지 않는다.

    유산소 카드는 단일 세트다(buildPresetSets에서 cardio는 count 1). 세트가 2개 이상인 구데이터에서는 오늘 원의 값을 그 날 해당 종목 done 세트의 합으로 계산한다.

    과거 요일 값은 recentCardioRuns(history:exerciseId:limit:)의 GymCardioRun{date, durationSec, distanceKm, kcal}에서 읽고 date로 요일에 매핑한다. 기본 limit 8은 이번 주+지난주를 담지 못한다 — 주 경계로 조회하는 함수를 신설하거나 limit을 확대할 것(둘 중 하나를 반드시 처리).

    입력한 칼로리는 세션 칼로리 추정에 그대로 쓰인다(GymCalorieEntry.enteredKcal 우선, 없으면 MET 추정). 이 동작은 바꾸지 않는다.

  페이스는 입력 항목이 아니다. 시간÷거리로 자동 계산되며(paceText), 이 카드에는 표시하지 않는다.

  6-1. 치수는 기기 폭에서 유도한다

  시안의 px 값은 모두 360px 폭 목업 기준의 결과값이다. 리터럴로 박지 말고 아래 식으로 산정할 것 — 스냅 오프셋을 316으로 고정하면 320~430pt 기기에서 하나씩 어긋난다.

        치수
        산정식 (360px 기준 결과)

      콘텐츠 폭 W	카드 폭 − 좌우 패딩 22px×2 (= 316)

      트랙 셀 폭 · 스냅	셀 폭 = W, 오프셋 = −index×W (0 / −316 / −632)

      증감 탭 영역	양변 각 W×0.33, 하한 44px (= 105)

      스와이프 임계	W×0.18 (= 56). 탭·드래그 분기 8px는 기기 무관 고정

      요일 원	지름 37px 고정(탭 하한 44px 미달 — 탭 타겟이 아니다). 7개를 space-between으로 배치해 넓은 기기에선 간격만 넓어진다. 간격이 4px 미달이 되는 좁은 폭에서만 지름을 32px까지 축소

      히어로 숫자	100px 기준. 값+단위 폭이 W−(탭 영역×2)를 넘으면 단계 축소(100 → 88 → 76). 줄바꿈·생략 금지

      수직 리듬	히어로·도트·요약 세 바가 space-evenly로 남는 높이를 나눠 갖는다 — 고정 마진 금지

  7. 제외 항목

    완료/저장 버튼, 스와이프 완료, 롱프레스 확정 — 두지 않는다.

    속도·경사 입력 UI — 콘솔 3값으로 한정하므로 카드에서 제거. 단 speed·incline 모델 필드와 cardioEntered의 해당 조건은 유지한다(기존 기록 호환).

    최근 8회 막대 그래프 — 주간 캘린더가 대체하므로 제거(설계 2026-08-10 §2 폐기).

    −/+ 버튼 — 증감은 빈 공간 탭으로만.

    카드 내 안내 문구, 박스, 구분선 — 라벨과 값만 남긴다.

    지난주 비교 문구·pill — 세션 중에는 오늘 값과 주간 숫자만 필요.

  8. 확인 체크리스트

    스와이프 3회에 히어로·캘린더 숫자·합계·단위가 모두 같은 지표를 말한다.

    오늘 미입력 지표에서 히어로 값과 오늘 원의 숫자가 일치하고, 그 값이 합계에 포함되지 않는다.

    참조값(회색)과 기록값(teal 채움)이 시각적으로 구분된다.

    좌우 105px 탭이 세 블록 전체 높이에서 동작하고, 드래그와 충돌하지 않는다.

    칼로리 3자리(예: 128), 주 합계 3자리 이상이 원·합계 영역에서 잘리지 않는다.

    우상단 세션 볼륨 비교가 유지된다.

    종료·마감 어느 경로로도 입력값이 보존된다(값 입력 후 즉시 종료, 값 입력 후 명시적 마감 두 경로 모두).

    사이클·엘립티컬 기록이 트레드밀 카드의 캘린더·합계에 섞이지 않는다.

    375pt·430pt 폭 기기에서 스와이프 시 활성 셀이 정확히 맞고(오프셋이 기기 폭에서 유도됨), 원 7개가 찌그러지지 않는다.

    시간 입력이 분으로 표시되고 초로 저장된다(32분 → duration 1920).

    해당 지표 기록이 없는 과거 요일이 —로 표시된다(0이나 추정값이 아니다).

  9. 구현 순서 · 함께 갱신할 것

    주간 집계 함수 신설(주 경계 조회 + 지표별 요일 값 + 오늘 제외 규칙) — 순수 로직, 테스트 우선.

    PWA 카드 마크업·제스처 교체(session.js) → 목업 반영(mocks/session.html).

    Swift 포팅(SessionLogic → CardioPanel).

    설계 문서 개정 — specs/2026-08-10-treadmill-record-design.md가 5필드 + 최근 8회 막대를 규정하고 있어 3필드 + 주간 캘린더 + 지표 로테이션으로 대체 기술이 필요하다. 스와이프 관련 조항(§6-3·§6-4)도 유산소 예외를 명시할 것.

  초기 상태: 카드 진입 시 활성 지표는 항상 시간. 지표 선택은 카드 로컬 상태로만 두고 저장하지 않는다(세션 데이터·localStorage 모두).
