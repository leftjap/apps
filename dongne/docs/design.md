# 동네 (가제) 설계

켜 두고 보기만 하는 서울 동네 지도. 동네 경계 안에 그 동네에 대해 오늘 쓰인 글의 단어가 천천히 떠올랐다 사라지고, 접속한 순간부터 무엇이 몇 번 떠올랐는지 쌓여 보인다.

## 정해진 것 (2026-11-14 지오 결정)

- 불멍처럼 켜 두고 보는 화면이다. 사용자는 입력·검색·투표를 하지 않는다. 퀴즈 같은 게임 규칙도 없다. 이 상태로 먼저 만들고, 재미 요소는 그다음에 붙여 본다.
- 출생 실시간 지도처럼 **접속한 순간 0에서 시작해 누적**된다. 과거 기록은 화면에 없고, 새로고침하면 다시 0이다.
- 교통·유동인구는 다루지 않는다 (마포 라이브 3D 에서 한다).
- 월 0원으로 운영한다.

## 화면 동작

- 단어 하나 = 오늘 그 동네에 대해 쓰인 실제 글 한 건에서 나온 단어. 지어낸 단어나 다른 동네 단어를 그 동네 안에 띄우지 않는다.
- 띄우는 시점은 출생 지도와 같은 방식이다. 동네마다 실제 글이 올라오는 속도(시간당 건수)에 맞춰 무작위 시점에 띄운다. 글이 많은 동네는 자주, 적은 동네는 가끔 뜬다. 화면 한쪽에 "오늘 쓰인 글을 실제 속도대로 띄웁니다"를 적는다.
- 새 글에서 나온 단어일수록 진하게, 몇 시간 지난 글의 단어는 흐리게 띄운다.
- 글이 너무 적은 동네는 같은 구의 글을 가져와 구 경계 전체에 넓고 흐리게 띄운다 (위치가 덜 정확하다는 것이 보이게).
- 문구는 "지금 이 동네"가 아니라 "오늘 이 동네"로 쓴다.

### 접속 후 누적 표시

- 접속 후 지난 시간, 지금까지 떠오른 단어 수 (출생 지도의 "접속 후 태어난 아기 수"에 해당).
- 단어별 누적 순위: 접속 후 가장 많이 떠오른 단어 상위 몇 개와 횟수. 같은 단어가 여러 동네에서 뜨면 합산한다.
- 동네별 누적: 떠오른 횟수만큼 동네 바탕색이 조금씩 진해진다. 오래 켜 둘수록 오늘 어느 동네가 활발했는지 지도에 남는다.
- 누적 값은 브라우저 메모리에만 있고 저장하지 않는다.

## 데이터 (2026-11-14 확인)

| 출처 | 동네 검색 | 시각 정보 | 한도 |
|---|---|---|---|
| 네이버 검색 (NAVER API HUB, `naverapihub.apigw.ntruss.com/search/v1/{blog,cafearticle,news}`) | 블로그·카페·뉴스, 최신순, 한 번에 100건 | 블로그는 날짜만, 카페는 없음, 뉴스는 분 단위(네이버에 들어온 시각) | 하루 25,000회 |
| 카카오(다음) 검색 (`dapi.kakao.com/v2/search/{blog,cafe}`) | 블로그·카페, 최신순(recency), 한 번에 50건 | 작성 시각(datetime) 있음 | 문서에서 확인 못 함 |
| 구글 트렌드 KR RSS | 지역 정보 없음 | 분 단위 | 키 불필요 |

- 구글 트렌드 전국 키워드는 그 동네 글에 함께 나올 때만 쓴다. 빈 동네를 채우는 데 쓰지 않는다.
- 단어 고르기: 맛집·카페처럼 어디에나 나오는 단어는 같은 날 다른 동네와 비교해 뺀다(과거 기록 불필요). 협찬·부동산 같은 광고 글은 뺀다. 불용어 목록은 `probe/lib.mjs` 상단.

## 측정 (지금 단계)

설계의 숫자(띄우는 속도, 묶어서 보여 줄 동네)는 실제 글 양을 보고 정한다.

- 동네 목록: `pnpm gazetteer` (또는 `node probe/gazetteer.mjs`). 2026-10 행정동 427개를 사람들이 쓰는 이름으로 합쳐 246개(상계1동~10동 → 상계동)로 만들고, 행정동 이름으로 안 잡히는 생활권 이름 25개(홍대, 서울숲 등)를 더해 `probe/seoul-dongs.json` 에 쓴다. 신사동·삼성동처럼 서울 안에서 겹치는 이름과 서울 밖 동네와 겹치는 이름(47개)은 표시해 두며, 이런 동네는 글 수가 부풀 수 있다.
- 키: `~/.config/dongne/.env` (chmod 600) 에 `KAKAO_REST_API_KEY`, 또는 `NAVER_API_HUB_KEY_ID` + `NAVER_API_HUB_KEY`.
- 실행: `node probe/measure.mjs` (전체), `--only 연남동,홍은동`, `--limit 20`. 결과 요약은 터미널에, 전체는 `probe/out/measure-*.json` (커밋 안 함).
- 보는 값: 동네별 광고 제외 글 수 분포(카카오는 최근 24시간, 네이버 블로그는 어제 하루), 하루 24건(1시간에 1건)·144건(10분에 1건) 넘는 동네 수, 광고 비율, 동네마다 살아남은 단어 수, 시간대별 글 수.
- 하루 세 번(오전 9시, 오후 2시, 밤 10시 무렵) 돌려 시간대별 차이를 본다.
- 예상 호출 수: 카카오는 동네 271곳 × 2종 × 1~10쪽, 네이버는 블로그 어제 하루치를 위해 최대 10쪽.

## 아직 정하지 않은 것

- 수집을 어디서 돌릴지: 이 저장소의 Pages 배포는 main 푸시마다 모든 앱을 다시 배포하므로, GitHub Actions 가 자료를 커밋하는 방식은 맞지 않는다. Cloudflare Workers 의 정기 실행 + KV 같은 무료 경로를 측정 뒤에 고른다.
- 동네를 몇 곳까지 정기 조회할지: 한도(네이버 하루 25,000회)와 측정한 글 양으로 정한다.
- 서비스용 카카오 앱: 지금 있는 카카오 앱은 도서 검색용(1573685) 하나다. 측정에는 그 키를 써도 되지만, 서비스에는 별도 앱을 쓰는 편이 한도 관리에 낫다.
