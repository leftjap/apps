# mapo 개발 원칙 (2026-11-19 지오 확정)

마포 작업을 시작하는 모든 세션과 하위 작업은 이 파일부터 따른다. 설계는 `docs/design.md`, 다른 구역으로 넓힐 때는 `docs/new-area-checklist.md`.

## 4단계 순서
1. 공간·도로·인도·고정시설물 구획 (찻길 면, 연석, 보도 면, 섬·분리대, 차로 모양, 신호 기둥·정류장·출입구·환기구 자리)
2. 노면 표시·횡단보도·버스정류장·신호 체계 완성 (차·사람 0명)
3. 차량·버스 주행 검증
4. 보행자 이동·승하차 검증

앞 단계가 지오 승인을 받기 전에는 다음 단계 코드를 쓰거나 main 에 넣지 않는다. 지금 단계는 아래 '현재 단계' 줄이 정한다.

## 단계별 승인 게이트
- 단계를 마치면 계획 세션이 주요 교차로 화면(png)을 Read 로 직접 열어 검수하고, 결함이 없을 때만 지오에게 보고하고 승인을 요청한다. 파일이 생겼는지만 보고 넘어가지 않는다.
- 화면에서 찾은 결함은 그 자리만 고치지 않는다. 같은 종류를 판 전체에서 세는 정적 시험으로 만들고, 실패를 확인한 뒤 고친다.
- 수치(시험 통과)는 승인을 대신하지 않는다.

## 하드코딩 금지
특정 교차로 좌표·구간 번호·횡단보도 번호를 if 문으로 예외 처리하지 않는다. 지도 자료(선형·연결선·경계)나 공통 규칙을 고친다.

## 1·2단계 동안의 시험과 측정
- 확인은 몇 초 만에 끝나는 정적 시험과 화면으로 한다. 차·사람 시뮬레이션 측정(9판·60판·씨앗 평균)은 돌리지 않는다.
- CI 는 지도 시험(`pnpm test:map`)만 실패를 표시하고, 차·사람 시뮬레이션 시험(`pnpm test:sim`)은 결과를 기록만 한다. 3단계에서 다시 판정 기준으로 쓴다. 로컬 `pnpm test` 는 전부 돈다.
- 기본 주소는 빈 지도다(차·사람 0). 차는 `?cars=1`, 사람은 `?people=1` 일 때만 돈다.

## 작업 분담
- 원인 진단, 지시문 작성, diff 검토, 화면 검수, 커밋은 계획 세션(Claude)이 한다.
- 한 파일로 좁혀진 수정과 관련 시험 통과 반복은 Cline CLI 에 맡긴다(명령은 `~/.claude/CLAUDE.md` 'Cline CLI 위임'). 결함 하나에 한 번, 같은 결함에서 두 번 막히면 멈추고 보고한다.
- 몇 시간씩 측정을 돌리는 하위 Claude 작업은 쓰지 않는다(한 작업 30만~80만 토큰을 쓴 일이 되풀이됐다).

## 현재 단계
1·2단계 진행 중. 3·4단계 코드(차 규칙, 차 난수, 사람 규칙)는 승인 전까지 넣지 않는다.
