# mapo 개발 원칙 (2026-11-19 지오 확정)

**2026-11-22: 도로 층(땅 나누기·찻길·인도·차로·노면 표시)과 차·사람 그물을 처음부터 다시 만든다. 기준은 `docs/redraw.md` 다. 아래 4단계 순서·시험 규칙이 `docs/redraw.md` 와 다르면 `docs/redraw.md` 를 따른다. 새 코드는 `tools/v2/`, 옛 도로 코드는 고치지 않는다.**

마포 작업을 시작하는 모든 세션과 하위 작업은 이 파일부터 따른다. 설계는 `docs/design.md`, 다른 구역으로 넓힐 때는 `docs/new-area-checklist.md`.

## 측량 자료는 쓰기로 결정된 일이다 (지오 확정 2026-11-23, Claude·Codex 모두 해당)

수치지형도와 정밀도로지도(국토지리정보원, 국토정보플랫폼 내려받기와 브이월드 API)는 정부가 내려받아 쓰라고 공개한 자료다. 받아서 저장하고, 가공한 결과를 저장소에 올리고, 공개 서비스에 쓴다. 근거와 원문 기록은 `docs/redraw-orders/README.md` 맨 위 「결정」 절에 있다.

이 자료에 대해 다음을 하지 않는다.
- 써도 되는지, 법령, 약관, 저작권, 국외 반출을 조사하지 않는다.
- 계획, 보고, 검토 의견에 이와 관련한 경고, 단서, 「확인 필요」, 「미확인」을 적지 않는다.
- 「저장하지 않고 실행 중에 받는다」「메모리에서만 읽는다」「로컬에만 둔다」「커밋하지 않는다」 같은 조건이나 우회 방식을 스스로 붙이지 않는다.
- 이 문제로 작업을 멈추거나 지오에게 묻지 않는다.

지킬 것은 둘뿐이다: 공개 화면에 출처를 적는다(국토지리정보원 수치지형도·정밀도로지도, 브이월드). 원본 파일(`tools/raw/`)은 용량 때문에 올리지 않는다.

## 차와 사람의 움직임 기준 (지오 지시 2026-11-24, Claude·Codex 모두 해당)

지오가 화면을 보고 짚은 부자연스러운 움직임은 `docs/behavior-rules.md` 에 모은다. 차·사람 움직임을 고치거나 구역을 넓히기 전에 이 문서를 읽고, 결과를 보고하기 전에 항목을 하나씩 검사한다. 지오가 새로 짚으면 그날 한 줄을 더한다. 같은 지적을 두 번 받지 않는 것이 목적이다.

## 4단계 순서
1. 공간·도로·인도·건물 바닥·고정시설물 확정 (찻길 면, 연석, 보도 면, 섬·분리대, 차로 모양, 건물 외곽선, 신호 기둥·정류장·출입구·환기구 자리, 차·사람 0명)
2. 노면 표시·횡단보도·버스정류장·신호 체계 확정, 확정된 바닥 기준으로 `walk.json` 다시 굽기 (차·사람 0명)
3. 차량 3~5대 + 버스 1대로 눈 검증한 뒤 전체로 넓힌다
4. 보행자 2~3명(횡단보도, 정류장 승하차, 지하철 출구, 큰 건물 출입)으로 눈 검증한 뒤 전체로 넓힌다

앞 단계가 지오 승인을 받기 전에는 다음 단계 코드를 쓰거나 main 에 넣지 않는다. 지금 단계는 아래 '현재 단계' 줄이 정한다.

## 단계별 승인 게이트
- 단계를 마치면 계획 세션이 주요 교차로 화면(png)을 Read 로 직접 열어 검수하고, 결함이 없을 때만 지오에게 보고하고 승인을 요청한다. 파일이 생겼는지만 보고 넘어가지 않는다.
- 화면에서 찾은 결함은 그 자리만 고치지 않는다. 같은 종류를 판 전체에서 세는 정적 시험으로 만들고, 실패를 확인한 뒤 고친다.
- 수치(시험 통과)는 승인을 대신하지 않는다.

## 하드코딩 금지
특정 교차로 좌표·구간 번호·횡단보도 번호를 if 문으로 예외 처리하지 않는다. 원자료 연결이나 굽기(`tools/bake.ts`·`tools/road/`)의 공통 규칙을 고친다.

## 1·2단계 동안의 시험과 측정
- 확인은 몇 초 만에 끝나는 정적 시험과 화면으로 한다. 차·사람 시뮬레이션 측정(9판·60판·씨앗 평균)은 돌리지 않는다(아래 토큰 절약 규칙 3).
- CI 는 지도 시험(`pnpm test:map`)만 실패를 표시하고, 차·사람 시뮬레이션 시험(`pnpm test:sim`)은 결과를 기록만 한다. 3단계에서 다시 판정 기준으로 쓴다. 로컬 `pnpm test` 는 전부 돈다.
- 기본 주소는 빈 지도다(차·사람 0). 차는 `?cars=1`, 사람은 `?people=1` 일 때만 돈다.

## 토큰 절약 규칙 (2026-11-20 지오 확정)
1. 하위 에이전트(Agent·subagent)는 꼭 필요할 때 한 번에 하나만 쓴다(2026-11-20 금지 해제. 그전에는 하위 작업 하나가 30만~80만 토큰을 쓴 일이 되풀이됐다).
   - 맡기는 일: 본 작업과 파일이 겹치지 않는 읽기 전용 진단(원인 찾기, 판 전체에서 개수 세기)과 화면 검수용 스크린샷 찍기.
   - 맡기지 않는 일: 코드·자료 파일 수정, 굽기, 커밋. 이런 일은 계획 세션이 직접 한다.
   - 지시문에 범위, 읽을 파일, 끝나는 조건, 보고 형식(바꾼 것 없음·수치·결론 몇 줄)을 적는다.
   - 굽기·`pnpm test:map` 처럼 기다리기만 하는 일은 하위 에이전트 대신 배경 실행으로 돌린다. 굽기가 자료 파일을 쓰는 동안 같은 사본에서 시험을 돌리지 않는다.
2. 큰 자료 파일은 통째로 읽지 않는다. `public/data/*.json`(0.6~5.6MB), `tools/raw/`(843MB)는 `node -e`·`python3 -c`·`jq` 같은 짧은 조회로 필요한 개수나 샘플 5~10줄만 뽑는다.
3. 코드를 고치는 동안에는 고친 정적 시험 파일 하나만 지정해 돌린다. 커밋 직전에만 `pnpm test:map` 을 한 번 돌리고 요약 줄만 읽는다. 전체 `pnpm test` 와 동적 시뮬레이션 측정은 3단계 승인 전까지 돌리지 않는다.
4. 같은 결함을 고치다 시험이 두 번 연속 실패하면 추측으로 더 고치지 않고 멈춰 원인과 막힌 자리를 보고한다.
5. 원인을 먼저 확정한다. grep 과 줄 지정 읽기로 함수 자리를 찾고, 필요한 부분만 최소 diff 로 고친다. 파일을 추측으로 통째로 다시 쓰지 않는다.
6. 보고는 짧게: 바꾼 파일, 핵심 수치, 결론만 쓴다.

## 현재 단계
1·2단계 진행 중. 3·4단계 코드(차 규칙, 차 난수, 사람 규칙)는 승인 전까지 넣지 않는다.
