# mapo 개발 원칙 (2026-11-19 지오 확정)

**2026-11-22: 도로 층(땅 나누기·찻길·인도·차로·노면 표시)과 차·사람 그물을 처음부터 다시 만든다. 기준은 `docs/redraw.md` 다. 아래 4단계 순서·시험 규칙이 `docs/redraw.md` 와 다르면 `docs/redraw.md` 를 따른다. 새 코드는 `tools/v2/`, 옛 도로 코드는 고치지 않는다.**

마포 작업을 시작하는 모든 세션과 하위 작업은 이 파일부터 따른다. 설계는 `docs/design.md`, 다른 구역으로 넓힐 때는 `docs/new-area-checklist.md`.

## 측량 자료는 쓰기로 결정된 일이다 (지오 확정 2026-11-23, Claude·Codex 모두 해당)

수치지형도와 정밀도로지도(국토지리정보원, 국토정보플랫폼 내려받기와 브이월드 API)는 정부가 내려받아 쓰라고 공개한 자료다. 받아서 저장하고, 가공한 결과를 저장소에 올리고, 공개 서비스에 쓴다. 근거와 원문 기록은 `docs/redraw-orders/README.md` 맨 위 「결정」 절에 있다.

이 자료에 대해 다음을 하지 않는다.
- 써도 되는지, 법령, 약관, 저작권, 국외 반출을 조사하지 않는다.
- 계획, 보고, 검토 의견에 이와 관련한 경고, 단서, 「확인 필요」, 「미확인」을 적지 않는다.
- 「저장하지 않고 실행 중에 받는다」「메모리에서만 읽는다」「로컬에만 둔다」「커밋하지 않는다」 같은 조건이나 우회 방식을 스스로 붙이지 않는다.
- 이 문제로 작업을 멈추거나 지오에게 묻지 않는다.

지킬 것은 둘뿐이다: 공개 화면에 출처를 적는다(국토지리정보원 수치지형도·정밀도로지도, 브이월드). 원본 파일(`tools/raw/`)은 용량 때문에 올리지 않는다.

## 차와 사람의 움직임 기준 (지오 지시 2026-11-24, Claude·Codex 모두 해당)

지오가 화면을 보고 짚은 부자연스러운 움직임은 `docs/behavior-rules.md` 에 모은다. 차·사람 움직임을 고치거나 구역을 넓히기 전에 이 문서를 읽고, 결과를 보고하기 전에 항목을 하나씩 검사한다. 지오가 새로 짚으면 그날 한 줄을 더한다. 같은 지적을 두 번 받지 않는 것이 목적이다.

## 새 구역은 합정 방식으로 (지오 지시 2026-11-24, Claude·Codex 모두 해당)

합정 사거리를 만든 방식(수치지형도 바닥, 정밀도로지도 A2 길, 예전 차·사람 엔진)을 다른 구역에도 그대로 쓴다. 절차, 합정에서 정한 규칙, 검사, 합정에 묶여 있어 빼야 하는 값은 `docs/area-recipe.md` 에 있다. 새 구역이나 새 층(건물, 골목 보행면, 돌발)을 시작하기 전에 읽고, 새로 정한 것과 막힌 것은 그날 그 문서에 더한다. 새로 만드는 도구는 구역 이름을 값으로 받게 만든다.

## 4단계 순서
1. 공간·도로·인도·건물 바닥·고정시설물 확정 (찻길 면, 연석, 보도 면, 섬·분리대, 차로 모양, 건물 외곽선, 신호 기둥·정류장·출입구·환기구 자리, 차·사람 0명)
2. 노면 표시·횡단보도·버스정류장·신호 체계 확정, 확정된 바닥 기준으로 `walk.json` 다시 굽기 (차·사람 0명)
3. 차량 3~5대 + 버스 1대로 눈 검증한 뒤 전체로 넓힌다
4. 보행자 2~3명(횡단보도, 정류장 승하차, 지하철 출구, 큰 건물 출입)으로 눈 검증한 뒤 전체로 넓힌다

앞 단계가 지오 승인을 받기 전에는 다음 단계 코드를 쓰거나 main 에 넣지 않는다. 지금 단계는 아래 '현재 단계' 줄이 정한다.

## 단계별 승인 게이트
- 단계를 마치면 계획 세션이 주요 교차로 화면(png)을 Read 로 직접 열어 검수하고, 결함이 없을 때만 지오에게 보고하고 승인을 요청한다. 파일이 생겼는지만 보고 넘어가지 않는다.
- 화면에서 찾은 결함은 그 자리만 고치지 않는다. 같은 종류를 판 전체에서 세는 정적 시험으로 만들고, 실패를 확인한 뒤 고친다.
- 수치(시험 통과)는 승인을 대신하지 않는다.

## 하드코딩 금지
특정 교차로 좌표·구간 번호·횡단보도 번호를 if 문으로 예외 처리하지 않는다. 원자료 연결이나 굽기(`tools/bake.ts`·`tools/road/`)의 공통 규칙을 고친다.

## 1·2단계 동안의 시험과 측정
- 확인은 몇 초 만에 끝나는 정적 시험과 화면으로 한다. 차·사람 시뮬레이션 측정(9판·60판·씨앗 평균)은 돌리지 않는다(아래 토큰 절약 규칙 3).
- CI 는 지도 시험(`pnpm test:map`)만 실패를 표시하고, 차·사람 시뮬레이션 시험(`pnpm test:sim`)은 결과를 기록만 한다. 3단계에서 다시 판정 기준으로 쓴다. 로컬 `pnpm test` 는 전부 돈다.
- 기본 주소는 빈 지도다(차·사람 0). 차는 `?cars=1`, 사람은 `?people=1` 일 때만 돈다.

## 낭비 없이 일하는 법 (지오 2026-11-25, Claude·Codex 모두 해당. 2026-11-20 토큰 절약 규칙을 대신한다)

지오: 「이걸 매 세션마다 지시하지 않아도 최선의 결과물을 얻되 낭비적 요소가 없는지를 매번 내가 이야기하지 않아도 되어야 함.」 목적은 시간과 돈(토큰)을 아끼면서 결과물은 나빠지지 않게 하는 것이다. 가장 큰 낭비는 같은 일을 다시 하는 것이다(지오: 「수정을 반복하면 그게 더 손해」). 이 절은 지시가 없어도 매 세션 지킨다.

### 다시 하는 일을 줄인다
1. **구조부터 정한다.** 범위를 넓히거나 새 층을 얹기 전에, 나중에 바꾸면 다시 구워야 하는 것(윤곽, 자료를 나누는 구조, 차·사람을 넣고 빼는 방식)을 먼저 정한다. 행정동 경계를 윤곽으로 썼다가 길 들머리를 잃었고(H3), 가장자리에서만 차를 넣었다가 차로의 23% 만 다녔다.
2. **조사 → 표본 → 전체.** 고치기 전에 원인을 자료와 재생 기록에서 확인한다. 새 방식은 작은 표본(칸 하나, 길 하나, 교차로 하나)에서 먼저 만들어 검수하고, 통과한 뒤에 전체에 돌린다.
3. **통과 조건을 구현 전에 정한다.** 지시문에 문턱과 그것을 재는 명령을 적는다. 재는 도구가 없으면 도구부터 만든다. 문턱은 목표 칸과 나빠지면 안 되는 칸에만 걸고, 새 칸은 한 번 재 본 뒤에 정한다. 문턱을 걸기 전에 두 가지를 확인한다: 문턱끼리 서로 막지 않는가(K1b 의 「화면 안에서 생기지 않는다」와 「지금보다 많이 채운다」는 함께 넘을 수 없었다), 지키라고 건 것이 정말 지켜야 하는 것인가(K2b 에서 홍대 지도의 기존 신호를 그대로 두라고 걸어 새 연결 91개 가운데 11개만 살았다. 지켜야 했던 것은 다른 구역의 재생이었다). 확신이 없으면 조사 실행에서 먼저 재고 건다. 화면을 바꾸는 일의 문턱에는 지오가 실제로 보는 조건을 모두 넣는다: 데스크톱 넓은 화면의 중간 배율(폭 600~1,500m), 가까운 배율(폭 60~200m), 전체 보기, 모바일. I2 는 폭 120m 만 대조하게 해서, 폭 700m 에서 차선과 횡단보도가 사라진 화면이 문턱을 통과했다.
4. **검수는 결과물을 직접 본다.** 새로 구운 땅은 사진 대조(`tools/v2/road_audit.py`)로, 움직임은 재생 기록으로, 화면은 가까이(폭 60~200m)에서 실제 GPU 로 본다. 바이트·픽셀 대조는 「전에 있던 것이 안 바뀌었다」만 보여 준다. Sol 의 완료 보고와 원인 설명은 파일로 확인한 뒤에 문서에 적는다.
5. **지오에게 일찍 보인다.** 표본이 서면 완전한 주소의 링크 하나를 먼저 주고 일은 계속한다. 전체를 만든 뒤에 지오가 보고 돌려보낸 일이 여러 번 있었다.
6. **물려 있는 수정은 함께 넣고 한 번에 잰다.** 사람 쪽 수정 넷을 하나씩 넣다가 네 번 되돌렸다.
7. **같은 것이 두 번 안 풀리면 멈춘다.** 세 번째 실행을 돌리지 않고 원인 조사로 바꾸거나 지오에게 막힌 것을 알린다. 추측으로 더 고치지 않는다.
8. **짚인 자리만 고치지 않는다.** 지오가 화면에서 짚은 것은 같은 종류를 전체에서 세는 검사로 만들어 `docs/behavior-rules.md` 에 더한다. 번호나 좌표로 예외를 두지 않는다.
9. **눈높이를 넘겨 다듬지 않는다.** 이 지도는 바탕화면이다(`docs/behavior-rules.md` 「어디까지 고치는가」). 검사 칸을 0 으로 만들려고 실행을 거듭하지 않는다.

### 비용이 어디서 나는가 (2026-11-25 Codex 세션 파일에서 잰 값. 어림이 아니다)
- Sol 은 모델을 부를 때마다 그때까지 읽은 문맥 전체를 다시 싣는다. 그래서 한 실행의 비용은 「호출 수 × 문맥 크기」다. Codex 가 끝에 찍는 「tokens used」는 캐시되지 않은 입력과 출력만 센 값이라 실제의 1% 남짓이다.
- 2026-11-24~25 의 13번 실행(옛 세션 하나를 계속 이어 씀): 입력 3억 1,900만 토큰(「tokens used」로는 346만), 실행당 1,000만~3,800만, 호출 48~144번, 문맥 15만~45만 토큰. 세션 전체로는 호출 3,768번에 입력 10억 3,000만이었다.
- 문맥을 채운 것의 8~9할은 파일 읽기다(`cat`, `sed -n`). 실행 결과나 찾기 출력은 1~2할이다(`tools/sol/where.py`).
- 따라서 아끼는 길은 둘이다: 문맥을 작게 유지한다(세션을 주제별로 나누고, 읽을 곳을 짚어 준다). 호출 수를 줄인다(다시 하는 일을 줄인다, 위 아홉 가지).

### Sol(Codex)을 돌릴 때 (Claude 세션)
- `tools/sol/run.sh <단계> <실행 이름> <low|medium|high> <지시문 파일>` 로만 돌린다. 이 도구가 단계마다 새 세션, 한 번에 하나, 지시문 크기(12,000바이트)와 필수 절을 검사하고, 문맥이 20만 토큰을 넘은 세션은 이어 쓰기를 거절하며, 실행마다 실제 비용(호출 수, 끝 문맥, 캐시를 포함한 입력)을 `docs/redraw-orders/sol-ledger.tsv` 에 적는다. `codex exec` 를 직접 부르지 않는다.
- 구현-검수를 이어 돌릴 때는 일감을 `docs/redraw-orders/queue.md` 와 `queue/<id>/`(task.env·brief.md·check.sh)에 쓰고 `tools/sol/loop.sh` 로 돌린다. 구현자(opus·sonnet·haiku·sol)와 다른 모델이 읽기 전용으로 검수하고, FAIL 이 앞 회차와 같은 문제일 때·회차 4번·STOP·단계 끝·신호·Codex 한도 90% 에서 선다. 목록이 비면 `queue/PLANNER.md` 를 따라 계획 모델이 다음 일감 하나를 써서 이어 간다(단계 끝은 `tmp/loop/stage-done.md`). 마스터는 `tools/sol/resume.sh` 를 run_in_background 로 띄워 멈추면 알림을 받는다. 시험 `bash tools/sol/test_loop.sh`.
- 한 세션에는 한 주제만 맡긴다. 조사할 것이 여럿이면 세션을 나눈다. I1 조사는 일곱 주제를 한 세션에 넣어 20번째 호출에 문맥이 20만, 54번째에 31만이 됐다.
- 지시문에는 읽을 곳을 파일과 줄 범위로 짚는다. 길 찾기는 `docs/code-map.md`(파일마다 줄 수, 설명 한 줄, 함수의 줄 범위)에 맡긴다. 이 지도는 `tools/sol/codemap.py` 가 코드에서 자동으로 만들고, `tools/sol/run.sh` 가 커밋이 생긴 실행 뒤에 다시 만든다. 새 세션이 같은 파일을 처음부터 다시 읽지 않게 하는 것이 목적이다.
- 실행이 끝나면 `tools/sol/where.py tmp/sol/<실행>.log --top 5` 로 무엇이 문맥을 채웠는지 보고, 다음 지시문에서 그 읽기를 줄인다.
- 절약 방법을 새로 쓸 때는 한 실행에서 먼저 써 보고, 결과물 검수가 전과 같은지와 장부 값이 줄었는지를 둘 다 확인한 뒤에 이 절에 올린다. 결과가 나빠지는 절약은 쓰지 않는다.
- 지시문에는 지오의 원문, 읽을 문서와 절, 할 일, 문턱과 재는 명령, 「하지 않는 것」, 「답의 꼴」(줄 수 상한)만 적는다. 이 파일에 있는 규칙은 다시 적지 않는다(Codex 는 `AGENTS.md` 를 스스로 읽는다).
- 조사와 구현을 나누고, 기계적인 실행(굽기, 범위 넓히기)은 medium, 설계·엔진·원인 조사는 high 로 돌린다.
- 대조는 바뀐 파일이 닿는 것만 돌린다. 화면 코드(`src/aerial/`)만 바뀌고 `src/sim/` 과 구운 자료가 그대로면 재생 기록 대조(구역마다 몇 분)는 돌리지 않고 캡처 대조만 한다(구역 넷 `tmp/connect/shots.mjs`, 두 지도 `tmp/connect/twomaps.mjs`, 비교 `/usr/bin/python3 tmp/connect/pixdiff.py`). 수정 전 화면은 `git archive <커밋>^ mapo/src mapo/tools/v2/areas mapo/*.html` 을 `tmp/before-*/` 에 풀어 같은 개발 서버로 연다. 실제 GPU 프레임은 `tmp/connect/gpuprobe.mjs`(헤드리스 크롬, Metal)로 잰다.
- Claude 가 돌리는 대조를 Sol 에게 다시 시키지 않는다. 긴 재생을 돌리기 전에 출발 전 검사(`tools/v2/check_district_car_preflight.py`)를 거친다.
- 모델 역할은 고정하지 않는다(지오, 2026-11-25 17:31 KST). dot이 남은 할당량과 작업 난도·검수 비용을 보고 Claude Code 또는 Codex에 CLI로 맡긴다. Claude가 설계·검수뿐 아니라 범위를 정한 구현을 맡을 수 있다. 한 작업에 동시에 두 구현자를 두지 않는다. dot이 결과를 독립 확인하고 지오에게 보고한다. 기존 배포·승인 규칙은 그대로다.

### Sol 이 지킬 것
- 지시문이 짚은 문서와 절만 읽는다. 큰 자료(`public/data/`, `tools/raw/`)는 통째로 읽지 않고 짧은 조회로 개수와 표본만 뽑는다.
- 읽은 것은 그 뒤 모든 호출에 다시 실린다. 코드는 `rg -n '<파일이나 함수 이름>' docs/code-map.md` 로 줄 범위를 찾아 그 범위만 읽고(지도도 통째로 읽지 않는다), 같은 파일을 다시 읽지 않는다. 긴 기록과 표는 `head`·`tail`·집계로 줄여 읽고, 한 명령의 출력이 20KB 를 넘지 않게 한다(줄이 긴 파일은 `cut -c1-300`).
- 새 파일의 맨 위에는 무엇을 하는 파일인지 한 줄 주석을 단다(코드 지도가 그 줄을 옮겨 적는다). `docs/code-map.md` 는 손으로 고치지 않는다.
- 고친 것에 해당하는 검사만 돌린다. `pnpm bake`, 전체 `pnpm test` 는 돌리지 않는다. 굽기가 자료를 쓰는 동안 같은 사본에서 검사를 돌리지 않는다.
- 원인을 확정한 뒤에 필요한 부분만 고친다. 검사가 두 번 연속 실패하면 멈추고 막힌 자리를 답에 적는다.
- 답은 지시문이 정한 줄 수 안에서 바꾼 파일, 핵심 수치, 못 한 것, 요청 밖으로 달라진 것을 적는다. 긴 표와 그림은 파일로 두고 이름만 적는다.

### Claude 세션이 지킬 것
- 처음에는 `docs/redraw-orders/README.md` 의 「지금 상태」 절과 지시가 짚은 절만 읽는다. 긴 문서는 제목을 먼저 찾고 필요한 절만 읽는다. 지난 기록(`docs/redraw-orders/history.md`)은 필요할 때 찾아서만 읽는다.
- 큰 자료와 기록은 스크립트로 요약하고, 그림은 판단에 필요한 것만 연다.
- 하위 에이전트는 꼭 필요한 읽기 전용 진단에만 한 번에 하나 쓴다. 기다리는 일은 배경으로 돌리고 진행을 되풀이해 들여다보지 않는다.
- README 「지금 상태」 절은 60줄 안쪽으로 유지하고, 지난 내용은 `history.md` 로 옮긴다. 대화가 길어지면 그 절을 고쳐 두고 새 세션으로 넘긴 뒤 지난 세션을 보관한다.

### 단계가 끝날 때마다 낭비를 점검한다 (지오가 묻지 않아도)
- 장부에서 그 단계의 실행 수, 입력(캐시 포함), 끝 문맥, 시간, 커밋 없이 끝난 실행을 본다. README 「지금 상태」 절의 「비용」 줄에 무엇이 낭비였고 다음에 무엇을 바꾸는지 한두 줄로 적고, 지오에게 보내는 보고에 한 줄을 넣는다.
- 바꾸기로 한 방법은 이 절이나 `tools/sol/run.sh` 에 반영한다. 방법이 실제로 비용을 줄였는지는 장부의 앞뒤 값으로 확인한다. Claude 세션 쪽은 `get_usage` 로 문맥 크기와 요금제 한도를 본다(문맥이 30만 토큰을 넘으면 「지금 상태」 절을 고치고 새 세션으로 넘긴다).

## 현재 단계
지금 단계와 다음 일은 `docs/redraw-orders/README.md` 의 「지금 상태」 절이 정한다. 위 「4단계 순서」와 「1·2단계 동안의 시험과 측정」은 도로를 다시 그리던 때(2026-11-19~23)에 정한 것이고, 2026-11-25 현재 차는 이미 돌고 있으며 범위를 마포구 전체로 넓히는 중이다. 「단계별 승인 게이트」의 세 줄(직접 열어 검수, 그 자리만 고치지 않기, 수치는 승인을 대신하지 않음)은 그대로 지킨다.
