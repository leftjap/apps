# 서교동사거리 자동 도면 (Codex 지시서, 2026-11-23)

앞 작업(60e61ae0)은 항공사진을 눈으로 읽어 좌표를 손으로 적은 도면이다. 자리는 맞았지만 교차로마다 사람이 수백 개 좌표를 적어야 하고, 결과가 그림이라 차로 자료가 되지 않는다. 이번에는 **같은 156m 범위를 공개 자료에서 자동으로 만들고, 사진과 다른 곳만 짧은 「고친 목록」으로 바로잡는다.** 결과는 그림이 아니라 좌표 자료다.

손으로 적은 도면(`tools/v2/seogyo_trace.py`)은 지우지 않는다. 이번 작업에서 「사진을 읽은 값」의 기준으로 쓴다.

## 1. 지금까지 잰 것 (Claude 검증 세션이 직접 잼)

## 2. 만들 것

1. **굽는 도구** `tools/v2/` 에 새 파일. 입력은 가운데 경위도와 한 변 길이(서교동: `src/aerial/map.ts` 의 `PILOT_SITES.seogyo`, 156m)와 고친 목록 파일이다. 서교동 전용 좌표나 if 문을 코드에 넣지 않는다.
2. **결과 자료** `public/data/v2/seogyo-ground.json`(100KB 안쪽). 경위도(소수 7자리)로 적는다. 들어갈 것: 연석 선, 찻길 면, 종류별 노면선(종류·중분류·점열), 횡단보도(면과 줄), 정지선, 화살표, 그리고 적용한 고침의 번호. 선마다 서울시 자료 그대로인지 고친 것인지 표시한다.
3. **고친 목록** `tools/v2/seogyo-fixes.json`. 한 건은 「무엇을(종류 + 그 선 위의 경위도 한 점), 어떻게(옆으로 옮김·길 방향으로 옮김·숨김·추가·면 넓힘), 얼마나(m 또는 몇 점짜리 선), 왜, 사진 어디에서 봤는지」다. 1절의 8~12건은 예상치다. 각 고침에 사진 근거가 있을 때만 적용한다. **20건을 넘으면 멈추고 보고한다**(자료가 이 방식에 맞지 않는다는 뜻이다).
4. **화면** `aerial.html?surface=road` 의 「도로 그림」「겹쳐 보기」를 이 자료로 그린다(SVG 그림을 까는 대신 선과 면을 실제 폭으로 그린다). 손 도면은 「손 도면」 겹치기로 남겨 비교할 수 있게 한다. 사진 모드와 카메라는 그대로 둔다.
5. 선 폭·겹선 간격·점선 길이는 새로 정하지 않고 기본 화면의 값(`src/data/marks.ts` 의 `lineStyle`, `docs/design.md` 「그리기」: 정지선 0.45m, 나머지 0.15m, 겹선 사이 0.36m, 차선 점선 3m/5m, 유도선 1m/1m)을 쓴다. 횡단보도 줄도 기본 화면이 서울시 면으로 그리는 규칙이 있으면 찾아서 같은 규칙을 쓴다.

## 3. 항목별 규칙

- **중앙선**: 서울시 선 한 줄에서 양옆으로 같은 거리만큼 띄워 두 줄을 만든다. 두 줄은 항상 나란하다. 횡단보도와 정지선을 넘지 않게 끊는다.
- **차선·버스선**: 서울시 선 그대로. 정지선(없으면 횡단보도) 앞에서 끊는다. 교차로 안으로 들어가지 않는다.
- **정지선**: 그 접근로 차선과 직각으로 그린다. 같은 방향에서 앞뒤로 나뉜 정지선은 서울시 각 조각이 담당하는 차로 폭을 유지하고, 고친 목록으로 앞뒤 위치를 옮긴다. 한 접근로의 정지선 조각들은 서로 나란해야 한다.
- **유도선**: 서울시 012 를 정지선·횡단보도 가장자리에서 끊는다.
- **횡단보도**: 줄은 길과 나란하게, 면 안에만 그린다. 「이단」 면은 두 반쪽의 줄이 반 칸 어긋난다(사진에서 읽은 줄 간격은 약 1.1m). 차선과 중앙선이 횡단보도 위를 지나가지 않는다.
- **연석**: 곧은 구간은 서울시 길가 선(009·010·011)을 바깥으로 한 값만큼 띄운다. 띄우는 값은 판 전체에 하나만 쓰고, 손 도면과의 부호 있는 거리로 정해 보고한다. 모퉁이는 두 곧은 구간에 닿는 둥근 호 하나로 잇는다(서울시 선의 모퉁이는 점 두세 개짜리 꺾은선이라 그대로 쓰지 않는다). 규칙으로 기준(5절)에 못 미치는 모퉁이는 코드에 예외를 넣지 말고, 호의 반지름을 고친 목록 1건으로 적는다.
- **찻길 면과 인도**: 찻길 면은 연석 선으로 닫은 면이다. 범위 안에서 찻길 바깥은 화면 배경색으로 칠한다. 대지와 인도 바깥 경계를 구분할 자료가 없으므로 이 영역의 보행 가능 여부는 미확인으로 둔다. 대지 구분(손 도면의 회녹색)은 근거 자료가 없으므로 만들지 않는다. 건물(정부 GIS건물통합정보)은 지금처럼 위에 올리기만 하고 길을 잘라내지 않는다.
- **가려진 곳**: 사진에서 차·나무에 가려 확인하지 못한 선은 서울시 자료를 그대로 쓰고, 겹쳐 보기에서 「사진으로 확인 못 함」으로 구분해 보인다.

## 4. 지킬 것

- 순서: 먼저 5절의 수치를 재는 검사(`tools/v2/check_seogyo_auto.py` 같은 한 파일)를 만들고 실패를 확인한 뒤 굽는 도구를 만든다.
- 옛 도로 코드(`tools/bake.ts`, `tools/road/`, `src/sim/`, 기본 화면의 `src/render/`)는 읽기만 하고 고치지 않는다. 새 코드는 `tools/v2/` 와 `src/aerial/` 에 둔다.
- 수치지형도·정밀도로지도(`tools/raw/ngii/`)는 대조 수치를 내는 데만 쓴다. 그 좌표를 결과 자료나 고친 목록에 옮기지 않는다(내려받기 준수사항).
- 인증키, 사진 타일, 캡처, `tools/raw/`, `tmp/` 는 커밋하지 않는다. 브이월드 타일을 저장하지 않는다.
- 굽기(`pnpm bake`), 전체 `pnpm test`, 차·사람 시뮬레이션은 돌리지 않는다. 자기가 만든 검사 파일만 돌린다.
- `git stash`, `reset --hard`, 브랜치 전환, force push 금지. 자기가 만든 파일만 커밋하고 main 에 푸시한다.
- 같은 기준이 두 번 고쳐도 통과하지 않으면 더 고치지 말고 멈춰서, 무엇이 왜 안 되는지 보고한다.
- 이번 범위가 아닌 것: 차·사람 경로, 신호등, 합정역 판정, 골목 입구, 인도 바깥 경계.

## 5. 끝나는 조건

검사가 아래 표를 한 줄씩 출력하고, 모두 기준 안이어야 한다. 기준은 「자동 도면 ↔ 손 도면」 거리다. 손 도면에서 가려진 구간(`OCCLUDED`)과 동쪽 접근로 북쪽 절반은 사진 일치 판정에서 뺀다. 손 도면의 횡단보도 중심점 139개 전부에 대해 대응하는 면 안에 드는지 검사하고, 사진으로 확인한 표본과 가려진 표본의 개수를 나눠 적는다. 차선·정지선·유도선은 종류와 연결 위치가 같은 선끼리 비교한다. 예상 개수와 실제로 짝지은 개수를 함께 기록하고, 빠진 선은 실패로 표시한다.

| 항목 | 기준 |
|---|---|
| 중앙선(접근로마다) | 중앙값 0.6m 이하, 두 줄 중심 사이 거리 0.36±0.02m, 그 거리의 최댓값 − 최솟값 0.02m 이하 |
| 차선·버스선(접근로마다) | 중앙값 0.4m 이하, 90% 1.0m 이하 |
| 정지선(선마다) | 중앙값 0.5m 이하, 같은 접근로 조각끼리 방향 차 1° 이하 |
| 유도선 | 손 도면 12줄 모두 중앙값 2.0m 이하 |
| 횡단보도 | 손 도면 줄 가운데 139개가 모두 대응하는 자동 도면 면 안, 면 가장자리가 줄 끝에서 1.0m 안. 이와 별도로 반쪽별로 실제로 칠한 줄 수·간격과 보이는 줄의 일대일 대응을 보고한다 |
| 연석(모퉁이마다) | 중앙값 1.2m 이하, 90% 1.5m 이하, 최대 2.0m 이하 |
| 겹침 | 횡단보도·정지선 위를 지나는 차선·중앙선 길이 0m, 찻길 면 밖으로 나간 노면선 길이 0m. 실제 도색 폭의 면으로도 겹침·이탈 면적을 재고, 경위도 반올림 오차로 처리한 양과 허용오차를 따로 적는다 |
| 고친 목록 | 20건 이하, 건마다 까닭과 사진 근거 |

수치가 통과해도 끝이 아니다. 폭 60m 화면에서 사진, 도로 그림, 겹쳐 보기 세 장과 네 접근로를 가까이 찍은 것 네 장을 `tmp/seogyo-auto/` 에 남긴다. Claude 검증 세션이 이 화면을 사진과 나란히 보고 판정한 뒤 지오에게 보낸다.

마지막으로, 같은 명령에 합정역(`PILOT_SITES.hapjeong`)을 넣어 고친 목록 없이 한 번 돌리고 겹쳐 보기 한 장만 남긴다. 판정하지 않는다. 코드에 서교동 전용 내용이 없는지 보는 용도다.

## 좌표를 옮길 때 주의

손 도면의 좌표는 SVG 안 `rotate(4.6 390 390)` 묶음 안쪽 값이다. 지상으로 옮기는 순서는 「4.6° 회전 → 한 칸 0.2m, 가운데 (390, 390) → 판을 −42° 돌림(`AERIAL_BEARING`) → `groundPoint(PILOT_SITES.seogyo)` 더하기」다. 회전을 빼먹으면 가운데는 맞고 가장자리에서 3~5m 어긋난다(검증 세션이 한 번 틀렸던 곳이다). 이 순서로 옮긴 중앙선이 서울시 중앙선과 0.1~0.6m 로 맞으면 변환이 맞은 것이다.
