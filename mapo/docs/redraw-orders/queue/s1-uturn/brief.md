# s1-uturn: 유턴구역선(B2 502)과 기타선(599)을 선으로 그린다

## 지오의 원문
「근데 도로는 조금 더 디테일이 있으면 좋겠어.」「이 지도를 보면서 사람들이 차가 정확히 가나 이런 거 보는 거 아냐, 적당히 차들이 많다, 실제 구현한 거 같다 이런 느낌이 있으면 되는 거야.」

## 배경 (조사는 끝났다. 다시 조사하지 않는다)
앞 일감 `s1-safety-border` 가 안전지대 테두리(531)를 넣은 뒤에도, 자료에는 있는데 화면에 그려지지 않는 B2 선 종류가 둘 남았다.

- **502 유턴구역선: 466줄, 4,961m.** 전부 type 212(백색 점선)다. `tools/v2/hapjeong_hd.py` 의 `KINDS`(30~35행)에 `'502'` 가 없어서 ink 가 `{'color': 0, 'width': 0.15, 'dash': 0, 'known': False}` 로 남고, `tools/v2/hapjeong_hd_a.py` 의 `LINE_KINDS`(18행)에도 없어서 A 보기의 `lines` 에서 아예 빠진다.
- **599 기타선: 1줄, 33m**, type 212. `KINDS` 에는 이미 있어 ink 는 제대로 찍히지만(백색 점선, known True), `LINE_KINDS` 에 없어서 A 보기에서 빠진다.

**사진 확인은 계획 세우기가 끝냈다.** 가장 많이 모인 자리(-199.0, -925.4)의 항공사진과 자료를 맞춰 보니, 502 는 황색 중앙선(501)이 끊기는 구간을 그대로 이어받는 선이다(501 은 (-182.5, -902.6)에서 끝나고 502 가 (-183.0, -902.9)에서 시작한다). 사진에는 그 자리에 찻길 한가운데를 따라 흰 점이 촘촘히 박힌 줄이 또렷하게 보인다. **사진에서 잰 점 간격은 약 0.5m, 점 길이는 약 0.25m 다.** 앱이 가진 점선 묶음은 `[0,0] [3,5] [1,1] [0.5,0.5]`(`src/aerial/ground-paint.ts` 의 `PAINT_DASHES`)인데, 0.5/0.5 는 폭 0.5m 인 자전거횡단도(앱 종류 13)에만 묶여 있어 쓸 수 없고 3m/5m 는 너무 성기다. 그래서 **1m/1m 점선에 폭 0.15m 인 앱 종류 12(유도선)** 를 쓴다. 이 선택은 정해진 것이고 다시 고르지 않는다.

## 할 일
1. **`KINDS` 에 `'502': ('유턴구역선', 12)` 를 더한다.** 색은 `TYPES` 가 정하므로 손대지 않는다(212 → 백색). 결과 ink 가 **색 2, 폭 0.15m, `dash` ≠ 0, `known` True** 여야 한다.
2. **`LINE_KINDS` 에 `'502'` 와 `'599'` 를 더한다.** 다른 종류는 더하지도 빼지도 않는다(535 자전거도로는 이 일감에서 넣지 않는다).
3. **다시 굽는다. 이 순서대로다**(모두 `--area tools/v2/areas/mapo-all.json`, 괄호는 앞 일감에서 걸린 시간):
   - `hapjeong_hd.py`(43초) → 바닥 자료의 502 ink 가 고쳐진다. 빼면 ink 가 옛 값(색 0)으로 남는다.
   - `hapjeong_hd_a.py`(3분 30초) → `lines` 에 502·599 가 들어오고 `paint` 가 다시 칠해진다.
   - `survey_road_paint.py`(4분) → 흰 노면 표시 분리가 다시 계산된다.
   - `pack_district_tiles.py`(21초).
   - 건물·지붕(`hapjeong_buildings`·`survey_roof_tiles`)과 다른 구역은 다시 굽지 않는다.
   - **검사도 이 네 가지를 스스로 다시 돌려 수치를 만든다.** 구현자가 쓴 수치 파일은 읽지 않는다.
4. **고치기 전 화면을 먼저 찍는다.** 자료를 다시 만들기 **전에** 개발 서버를 띄워(`pnpm exec vite --port 5199 --strictPort`) 아래 여덟 장을 `tmp/loop/s1-uturn/before/` 에 둔다. 이름과 주소를 **그대로** 쓴다(검사가 같은 주소로 다시 찍어 대조한다). 가까운 네 자리는 계획 세우기가 **창 안에 502 가 실제로 몇 미터 있는지 세서** 고른 곳이다(u1 123m, u2 97m, u3 83m, u4 238m).
   ```
   node tmp/connect/gpushot.mjs tmp/loop/s1-uturn/before \
     "u1=http://localhost:5199/apps/mapo/mapo-all.html?tiles=1&center=-199.0,-925.4&width=60" \
     "u2=…&center=-1819.4,-2471.5&width=60" \
     "u3=…&center=-1592.5,-1578.3&width=60" \
     "u4=…&center=-2586.8,-2634.4&width=200" \
     "mid-700=…&center=-199.0,-925.4&width=700" \
     "mid-1500=…&center=-199.0,-925.4&width=1500" \
     "full=…&center=-1192.55,-853.53&width=12000" \
     "mob-300=…&center=-199.0,-925.4&width=300"
   ```
   (`…` 는 앞 줄과 같은 `http://localhost:5199/apps/mapo/mapo-all.html?tiles=1` 이다. 여덟 장 모두 `gpushot.mjs` 기본 보기로 찍는다. 모바일 수치는 검사가 `measure.mjs mobile` 로 따로 잰다.)
5. **사진 대조 패널 두 장.** 계획 세우기가 자리를 적어 둔 `docs/redraw-orders/queue/s1-uturn/plan.json` 을 **그대로 쓴다**(고치지 않는다).
   ```
   tools/.venv/bin/python -B tools/v2/road_audit.py --area mapo-all \
     --plan docs/redraw-orders/queue/s1-uturn/plan.json \
     --out tmp/loop/s1-uturn/audit --workers 4
   ```
   나온 그림을 `tmp/loop/s1-uturn/shots/` 로 옮긴다: `U01/U01-001-photo.jpg` → `audit-1-photo.jpg`, `U01/U01-001-overlay.jpg` → `audit-1.jpg`, `U02/U02-001-photo.jpg` → `audit-2-photo.jpg`, `U02/U02-001-overlay.jpg` → `audit-2.jpg`. 검수자가 사진과 겹친 그림을 나란히 본다.
6. **측정 기록** `tmp/loop/s1-uturn/measure.md`(15줄 안쪽): 502 에 준 ink, A 보기 선 종류별 수의 전·후, 502·599 의 줄 수와 길이, 노면 도색 색별 면적의 전·후, 빗금·화살표 수가 그대로인지(바뀌었으면 어느 자리가 왜 바뀌었는지 자료에서 확인해 적는다), 캡처 여덟 장의 픽셀 차이, 겹친 그림에서 점선이 사진의 흰 점줄과 어긋나는 자리가 있으면 그 수, 못 한 것.

## 읽을 곳 (이것만 읽는다)
- `tools/v2/hapjeong_hd.py`: 30~40행(`KINDS`·`TYPES`), 148~156행(`marking_style`).
- `tools/v2/hapjeong_hd_a.py`: 18행(`LINE_KINDS`), 165~176행(`connected_paint`), 250~256행(`bake_a`).
- 앱의 노면 규격표가 궁금하면 `src/data/marks.ts` 의 `lineStyle`(81~98행)만 본다. 고치지 않는다.
- 함수의 줄 범위는 `rg -n '<이름>' docs/code-map.md` 로 찾는다. 다른 파일은 열지 않는다.

## 문턱 (재는 명령)
`bash docs/redraw-orders/queue/s1-uturn/check.sh` 종료 0. 검사 파일(`check.sh`·`uturn.py`·`plan.json`)을 고치지 않는다. 이 검사가 재는 것:

- **검사가 네 굽기 도구를 직접 다시 돌린 뒤** 결과 자료에서 개수를 센다(약 9분 걸린다).
- 자료(`uturn.py`): 바닥 자료의 선 19,980줄·횡단보도 1,629·자전거 182 그대로. 502 가 466줄·4,961m(±2%)이고 ink 가 색 2·폭 0.10~0.25m·`dash` ≠ 0·`known` True. 599 가 1줄이고 ink 가 같은 규격.
- A 보기에 502 466줄·599 1줄이 들어오고, **다른 종류의 줄 수는 전과 똑같다**(501 3,195 / 503 4,085 / 504 251 / 505 2,191 / 506 2,097 / 515 5,130 / 525 780 / 530 1,314 / 531 340). 요청에 없는 종류가 들어오지 않는다.
- 노면 도색 면적: 색 0 3,719.1㎡·**색 1(황색) 32,325.4㎡**·색 3 1,779.2㎡ 가 ±1.5㎡ 안에서 그대로, **색 2(백색)는 54,780~55,020㎡**(전 54,656.6, 점선 도색 +296㎡ 가 들어올 자리다. 계획 세우기가 같은 `footprint` 함수로 미리 재서 293.5 + 2.0㎡ 를 얻었다).
- 빗금 면 46·40·661개, 황색 빗금 250개, 열린 테두리 73·중앙 조각 694 가 전과 똑같다(502 는 빗금 판정에 들어가지 않는다). 화살표는 종류마다 **전과 ±4 안**이고 새 종류가 생기지 않는다. 숫자가 바뀌었으면 `measure.md` 에 자리와 까닭이 있어야 하고 검수자가 본다.
- 앞 일감 검사 다섯(`s1-outline`·`s1-tiles`·`s1-water`·`s1-paint`·`s1-approach`)을 그대로 다시 돌려 통과. (`s1-safety-border` 의 `border.py` 는 흰 도색 면적을 54,900㎡ 아래로 못 박아 두어 이번 변경과 어긋난다. 그래서 검사가 부르지 않고, 531 이 340줄 그대로인지와 황색 면적·빗금 수는 `uturn.py` 가 대신 본다. **`border.py` 를 고치지 않는다.**)
- 캡처 여덟 장에 페이지 오류가 없고, **가까운 네 자리가 고치기 전과 u1 0.10%, u2 0.07%, u3 0.06%, u4 0.05% 이상 다르다**(점선이 실제로 그려졌다는 뜻). **넓은 보기 셋은 폭 700m 0.25%·1,500m 0.15%·전체 0.05% 이하로만 다르다**(넓은 화면이 지저분해지지 않았다는 뜻).
- 여섯 보기 수치: 프레임 p95 ≤ 33ms, 첫 표시 ≤ 8,000ms, 먼 단계 ≤ 2,000,000바이트(지금 1,563,776).
- 기존 화면 넷(홍대 칸 150m·700m, 홍대 평면 700m, 양화 700m) 픽셀이 그대로, `src/` 안 바뀜, 다른 구역 자료와 `tools/v2/areas/mapo-all.json` 안 바뀜, 홍대 칸 자료 안 바뀜, `pnpm test:map` 통과.
- `pnpm test:map` 의 시험이 노면선 종류 목록을 못 박고 있으면 그 시험도 새 종류를 포함하게 고친다.

## 하지 않는 것
- **문턱을 못 넘으면 넘은 척하지 않는다. 앞 결과나 보관본을 섞지 않고, 수치 파일을 손으로 쓰지 않는다.** 막히면 막힌 자리와 잰 수치를 답에 적는다.
- **535 자전거도로(343줄·12,983m)는 이 일감에서 넣지 않는다.** 자전거 길은 이미 B3 면으로 칠해져 있어 따로 봐야 한다.
- 점선 묶음(`PAINT_DASHES`)이나 `lineStyle` 을 고치지 않는다. 새 규격을 만들지 않는다.
- 좌표·구역 이름·교차로 번호로 예외를 두지 않는다. 눈에 맞춰 폭이나 색을 바꾸지 않는다(자료의 색과 규격 폭을 쓴다).
- 차·사람 재생, `pnpm bake`, 전체 `pnpm test`, 건물·지붕 다시 굽기, 다른 구역 다시 굽기, 미리보기 도구, 소리.
- `tools/sol/`, 다른 일감 폴더, 이 일감의 `check.sh`·`uturn.py`·`plan.json` 을 고치지 않는다.

## 답의 꼴
