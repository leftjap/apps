# s1-decks: 높이가 다른 길(다리·고가·지하차도)이 땅 높이로 겹쳐 그려지는 자리를 재고 규칙 후보를 낸다

**재기만 한다. 코드와 구운 자료를 고치지 않는다.**

## 지오의 원문
「이 지도를 보면서 사람들이 차가 정확히 가나 이런 거 보는 거 아냐, 적당히 차들이 많다, 실제 구현한 거 같다 이런 느낌이 있으면 되는 거야.」

## 배경 (계획 세우기가 이미 확인한 것. 다시 세지 않는다)
검수 목록 16번은 「높이가 다른 길(강변북로, 나들목, 고가, 다리)은 땅 높이로 겹쳐 그려진다. S1 에서는 목록만 만들고 다음 단계에서 높이별로 나눈다」다. 앞 일감 `s1-review` 가 네 자리에서 실제로 그 현상을 보았다: 13 마포구청역(내부순환로 고가 도색이 아래 월드컵로와 같은 면에 포개짐), 15 디지털미디어시티역(증산로 지하차도 선이 성암로 위를 관통), 16 성산2교(아래 길 선이 고가 위로 이어짐), 20 양화대교북단.

원자료와 지금 코드에서 확인된 사실이다.
- 수치지형도 **A0070000 교량 300줄**: 도로교 195 · 보도교 82 · 철교 23. 칸은 `명칭·종류·연장·폭·설치연도·재질·하천명·기타·UFID` 이고 **높이 칸이 없다.**
- 수치지형도 **A0090000 136줄**: 고가차도 116 · 지하차도 20. 칸에 **`높이` 가 있지만 136줄 가운데 122줄이 0** 이고, 값이 있는 것은 4.5m×8 · 5.0m×2 · 6.0m×2 · 6.5m×1 · 17.3m×1 뿐이다. 명칭은 북부고가교(내부순환도로)·홍제천고가교·가양대교북단교차로·두모교·증산지하차도·성산지하차도 등이다.
- `tools/v2/survey_open_ground.py` 의 `open_ground`(50~66행)가 **도로교·보도교·고가차도만** `decks` 로 받고 **철교와 지하차도는 버린다.** `tools/v2/hapjeong_hd_a.py` 281~283행이 이 함수를 불러 A 자료에 넣는다.
- 지금 구운 `public/data/v2/mapo-all-a.json.gz` 의 `decks` 는 **287면**이고, 면마다 `kind`·`name`·`faces` 가 있다. `tools/v2/pack_district_tiles.py` 100~106행이 칸 자료로 포장하고, `src/aerial/yanghwa-terrain.ts` 84~92행이 **높이 0.012m 의 평평한 회색 면**으로 그린다. 즉 상판은 이미 자료에 있고 땅에 붙어 있다.

## 할 일
측정 스크립트 하나(`tmp/loop/s1-decks/measure_decks.py`)로 아래를 재고, 마지막에 **`DECKS-STATS {json}` 한 줄**을 찍는다(검사가 이 스크립트를 직접 다시 돌려 수치를 만든다).

1. **상판 목록.** 전역 윤곽 안에서 종류별(도로교·보도교·고가차도) 면 수와 면적. 버려지는 철교·지하차도의 수와 면적도 따로 센다.
2. **겹침.** 상판 면 안에 들어 있는 **지상 노면선 길이**(A 자료 `lines`, 종류별로), **찻길 면적**(`floor.road`), **흰·황색 도색 면적**(`paint`), **횡단보도 수**(`crossings`)를 센다. 이것이 「평면도에서 서로 관통하는」 몫이다. 상판 **밖**으로 1m 안에 닿는 몫은 세지 않는다.
3. **지하차도.** A0090000 구분=지하차도 20줄의 면 안에 있는 지상 노면선 길이와 찻길 면적을 같은 방법으로 센다.
4. **층을 가를 단서.** 위 길과 아래 길을 **자료로** 가를 수 있는지 판정한다. 네 가지를 본다: ① A0090000 의 `높이`(값이 있는 14줄이 어디인지 이름과 함께), ② 정밀도로지도 **A2 링크의 칸 이름 전체와 층·높이·고가로 읽힐 만한 칸의 값 분포**(`projected_lines(area, frame, 'a2')` 의 `row` 열쇠를 그대로 찍어 본다), ③ **B2 선의 칸**도 같은 방법으로, ④ 상판 면과 A2 링크의 포함 관계만으로 위 길을 고를 수 있는지(상판 안에 들어가는 A2 링크 수와 그 가운데 실제로 고가인 것의 비율을 표본 두 자리에서 눈으로 확인). **없으면 없다고 적는다.**
5. **표본 네 곳을 직접 본다.** 아래 명령으로 패널을 만들고 **여덟 장을 모두 열어 본다**(사진·겹친 그림). 자리마다 「위 길 이름 / 아래 길 이름 / 사진에서 보이는 것 / 모형에서 겹쳐 보이는 것」을 한 줄씩 적는다.
   ```
   tools/.venv/bin/python -B tools/v2/road_audit.py --area mapo-all \
     --plan docs/redraw-orders/queue/s1-decks/plan.json \
     --out tmp/loop/s1-decks/audit --workers 4
   ```
   나온 그림을 `tmp/loop/s1-decks/shots/` 로 옮긴다: `D01/D01-001-photo.jpg` → `d-01-photo.jpg`, `D01/D01-001-overlay.jpg` → `d-01-overlay.jpg`, D02~D04 도 같은 꼴(`d-02-…` ~ `d-04-…`).
6. **규칙 후보 두 가지 이상.** 후보마다 **고칠 파일과 함수와 줄 범위, 전역에 미치는 수치(올릴 면 수·숨길 선 길이·새로 생길 면적), 위험**을 적는다. 위험에는 적어도 이 셋을 본다: 차·사람 재생이 쓰는 `decks`(`tools/v2/check_district_car_preflight.py` 106~118행)에 미치는 영향, 칸 경계에서 상판이 잘리는 문제(`pack_district_tiles.py`), 멀리서 볼 때 상판이 뜬 그림자처럼 보이는 문제. 높이 값이 없는 상판에 **고정 높이를 주는 안**을 쓸 거면 그 수치와 근거(A0090000 의 실제 값 분포)를 적는다.
7. **표** `tmp/loop/s1-decks/decks.tsv`: 상판 이름(명칭)별로 종류·면적·겹친 노면선 길이·겹친 찻길 면적·표본 여부. 겹친 선 길이가 긴 차례로 **상위 30줄**과 머리줄.
8. **보고** `tmp/loop/s1-decks/summary.md`(25줄 안쪽): 위 1~6 의 결과, 자리 네 곳의 한 줄 판정, 규칙 후보, **못 잰 것과 까닭**. 긴 표는 `decks.tsv` 에 두고 이름만 적는다.

## 문턱 (재는 명령)
`bash docs/redraw-orders/queue/s1-decks/check.sh` 종료 0. 검사 파일(`check.sh`·`plan.json`)을 고치지 않는다. 이 검사가 재는 것:

- **검사가 `measure_decks.py` 를 직접 다시 돌려** `DECKS-STATS` 줄을 받고, `decks.tsv` 의 수치가 그 값과 1% 안에서 같은지 본다.
- JSON 에 다음 열쇠가 모두 있다: `decks`(`도로교`·`보도교`·`고가차도` 마다 `count`·`area`), `skipped`(`철교`·`지하차도` 마다 `count`·`area`), `overlap`(`lines`·`road`·`paint`·`crossings`), `underpass`(`lines`·`road`), `layer_fields`(`a0090000`·`a2`·`b2`·`a0070000`), `spots`(`D01`~`D04` 마다 `deck_area`·`lines`·`above`·`below`).
- 상판 수의 합이 **200 이상**이고 종류 세 가지가 모두 있다(구운 자료의 287면과 크게 다르면 윤곽이나 걸러내기를 잘못 본 것이다). `overlap.lines` 가 **0 보다 크다**(겹치는 선이 하나도 없다면 세는 방법이 틀렸다).
- 나머지 칸은 **처음 재는 값이라 문턱을 걸지 않는다.** 값이 0 이어도 되지만 열쇠는 있어야 하고, 0 이면 까닭이 `summary.md` 에 있어야 한다.
- 그림 여덟 장이 서로 다르고 폭 900px 이상이다.
- `summary.md` 에 「규칙 후보」와 자리 이름 넷(`양화대교`·`성산2교`·`마포구청`·`디지털미디어시티`), 그리고 「지하차도」가 있다.
- **코드·자료가 그대로다**: `src`·`tools/v2` 에 바뀐 파일도 새 파일도 없고(측정 스크립트는 `tmp/loop/s1-decks/` 에 둔다), 구운 자료가 바뀌지 않았고, 앞 일감의 검사 파일이 바뀌지 않았다. `s1-outline`·`s1-tiles` 검사와 `pnpm test:map` 이 통과한다.

## 하지 않는 것
- **문턱을 못 넘으면 넘은 척하지 않는다. 앞 결과나 보관본을 섞지 않고, 수치 파일을 손으로 쓰지 않는다.** 막히면 막힌 자리와 잰 수치를 답에 적는다.
- **상판을 실제로 올리지 않는다.** 이 일감은 재고 후보를 내는 데서 끝난다. 고치는 일은 다음 일감이다.
- 다시 굽지 않는다(`hapjeong_hd*`·`survey_road_paint`·`pack_district_tiles` 를 돌리지 않는다). 측정은 이미 구운 `public/data/v2/mapo-all-a.json.gz` 와 원자료를 읽어서 한다.
- 차·사람 재생, `pnpm bake`, 전체 `pnpm test`, 미리보기 도구, 소리.
- 좌표·이름·번호로 예외를 두는 안을 내지 않는다. 규칙 후보는 자료의 칸과 공통 규칙으로 적는다.
- `tools/sol/`, 다른 일감 폴더, 이 일감의 `check.sh`·`plan.json` 을 고치지 않는다.
