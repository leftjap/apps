# 지시서 4a: 땅 위 길을 판 전체로

기준 문서 `docs/redraw.md`(8판)를 처음부터 끝까지 읽고 시작한다. 이 지시서와 기준 문서로 정해지지 않는 선택이 나오면 스스로 정하지 말고 멈춰서 묻는다. 이 지시서에 없는 파일은 고치지 않는다. 3단계(3a·3b dc22e61d, 3c b1ee2db0)는 지오가 승인했다(2026-11-22).

## 목표

1~3단계의 규칙을 그대로 두고, 굽는 범위만 시제품 구역에서 판 전체(원점 둘레 반지름 2,000m 원)로 넓힌다. 결과는 `public/data/v2/` 의 `land.json`·`split.json`·`lanes.json`·`marks.json` 넷이다. 3D 화면 코드(`src/`)는 고치지 않는다(`?v=2` 가 같은 파일을 읽으므로 저절로 판 전체가 된다).

고가·다리(중심선 높이 0.3m 이상인 길, 큰길만 15km)는 이 지시서에서 다루지 않는다. 다음 지시서(4b)에서 다룬다. 지금 규칙으로는 다리 위 도로 부지가 함께 쓰는 면이나 인도로 나오고 차로가 없다. 그대로 둔다.

## 기획 세션이 저장소 밖 사본에서 먼저 돌려 본 것 (2026-11-22)

`land.py` 의 범위만 원으로 바꾸고 네 굽기를 그대로 돌렸다. 넷 다 오류 없이 끝났고 합쳐 41초였다(land 3.4, split 15.4, lanes 10.8, marks 11.5초).

| 굽기 | 사본에서 나온 수 |
|---|---|
| land | 도로 부지 다각형 200개, 2,380,316㎡, 길 위 시설 36동 |
| split | car 27개 886,741㎡, walk 1,173개 281,036㎡, mix 375개 1,197,749㎡, ped 75개 44,016㎡ |
| lanes | 구간 371개, 차로를 둔 구간 193개, 차로 가운데선 798개 |
| marks | 중앙선 148, 차선 509, 흰 실선 45, 정지선 520, 횡단보도 439 |

검사는 둘이 실패했다. 아래 「바꿀 것」 2·3·4 가 그 둘을 다룬다.
- `check_land.py`: 큰길 중심선 점 가운데 도로 부지·건물 안 94.13%(기준 98%). 판 북서쪽 홍제천 둘레의 성산로 2.1km 를 비롯해 땅 위 큰길 약 3.9km 가 실폭도로에 없다(자료가 그렇다. 기준 문서 5절).
- `check_lanes.py`: 같은 구간 안에서 만나는 차로 쌍 9개. 여섯은 판 가장자리 (1910, 541)에서 원에 비스듬히 잘린 찻길, 셋은 (−270, −1659)의 작은 찻길 조각(길이 43m 묶음 하나)이다.

수가 위 표와 조금 달라도 된다(아래 규칙 둘이 차로를 줄인다). 다각형 수나 넓이가 10% 넘게 다르면 멈추고 보고한다.

## 바꿀 것

1. **`tools/v2/land.py`: 범위를 원으로.** `AREA = (-2000, -2000, 2000, 2000)` 으로 바꾸고, 자르는 면 `RECT` 는 `shapely.geometry.Point(0, 0).buffer(2000.0, quad_segs=64)` 로 만든다(이름은 그대로 두어도 된다). `land.json` 의 `area` 에는 지금처럼 `AREA` 네 수를 적는다. `split.py`·`marks.py` 는 `area` 를 네모로 읽는데, 원 밖에는 도로 부지도 중심선도 없으므로 고치지 않는다.
2. **`tools/v2/lanes.py`: 판 가장자리 30m 안에는 차로를 두지 않는다**(기준 문서 4절 3, 6절). 값 둘을 파일 위쪽 값 목록에 더한다: `BOARD_R = 2000.0`, `EDGE_KEEP = 30.0`. 차로 단면을 정하는 곳(`build()` 안의 `point(d)`)에서, 구간 선 위의 그 자리 `sections[si]['line'].interpolate(d)` 가 원점에서 `BOARD_R - EDGE_KEEP` 보다 멀면 그 단면을 「없음」으로 다룬다. 폭을 재는 단계(25~75% 단면)는 바꾸지 않는다. 사본에서 이렇게 넣었더니 판 가장자리의 여섯 쌍이 사라졌다.
3. **`tools/v2/lanes.py`: 한 묶음 안의 차로 가운데선 둘이 만나면 그 묶음에는 차로를 두지 않는다**(기준 문서 4절 3). 끝의 종류(`n`·`j`·`x`)를 정하기 전에 본다: `lanes.py` 는 묶음을 만들고 끝의 종류를 정한 뒤에야 가운데선을 만들므로, 묶음을 거른 바로 뒤에 임시 가운데선을 만들어 판정한다(가운데선 계산을 함수 하나로 빼서 임시 계산과 마지막 계산이 같은 함수를 부른다. 2판, 구현 세션 질문에 답한 것). 뺀 묶음은 이웃 구간의 끝 종류를 정할 때 「이어지는 차로」로 세지 않는다. 뺀 묶음은 `lanes.json` 에 넣지 않는다(차로·경계선·`runs` 모두). 묶음이 하나도 남지 않은 구간은 차로가 없는 구간이다. 뺀 묶음의 수와 자리(구간 번호, 좌표)를 한 줄로 찍는다. 사본에서는 구간 한 곳 (−270, −1659)의 묶음 하나였다. 코드 구조 때문에 「끝의 종류를 정하기 전」에 뺄 수 없으면 멈추고 보고한다.
4. **`tools/v2/check_land.py`**:
   - 「큰길(등급 0~3) 중심선 점 … 도로 부지·건물 안 … 98% 넘게」 항목을 판정 없음으로 바꾼다(숫자만 찍는다). 도로 부지에 없는 길은 그리지 않기로 했고(기준 문서 5절), 판 전체에서는 자료에 없는 큰길이 있어서다.
   - 「구역 밖으로 나간 넓이」 항목은 네모 대신 1의 원으로 잰다.
5. **측량 대조 수치는 도엽이 있는 범위 안의 점만으로 낸다.** 수치지형도는 시제품 구역 12도엽뿐이다. `check_land.py`·`check_split.py`·`check_lanes.py` 에서 수치지형도와 재는 수치(경계 거리, 넓이 대조, 차로 수 대조)는 판 좌표 x −794~971, z −943~721 안의 점·면만으로 낸다(면은 이 네모로 자른다). 값은 세 파일에 `SHEETS = (-794, -943, 971, 721)` 로 둔다. PASS/FAIL 항목은 판 전체로 낸다.
6. **그림 스크립트 `tools/v2/plot_land.py`·`plot_split.py`·`plot_lanes.py`·`plot_marks.py`**:
   - 구역 전체 그림과 3×3 타일은 지금 코드 그대로 판 전체(`area`)를 그린다.
   - 측량과 견주는 그림(`land-vs-suchi`, `split-vs-suchi-car`, `split-vs-suchi-walk`)은 5의 `SHEETS` 범위만 그린다.
   - 확대 그림 목록(`ZOOM`)에 아래 자리를 더한다(가운데 좌표, 범위와 배율은 지금 확대 그림과 같게). 지금 있는 이름은 그대로 둔다.

## 순서

1. `node tools/v2/roads_json.ts` (이미 판 전체를 뽑는다. 다시 돌려 `tmp/v2/roads.json` 을 새로 만든다).
2. 바꿀 것 1을 하고 `land.py` → `check_land.py` → `plot_land.py`.
3. `split.py` → `check_split.py` → `plot_split.py`.
4. 바꿀 것 2·3을 하고 `lanes.py` → `check_lanes.py` → `plot_lanes.py`.
5. `marks.py` → `check_marks.py` → `plot_marks.py`.
6. 굽기 넷의 걸린 시간을 적는다. 합쳐 1분을 넘으면 멈추고 보고한다(기준 문서 10절).

검사가 FAIL 을 내면: 검사가 재는 방식이 규칙과 어긋난 것이면(자료가 규칙대로인지 한두 곳을 직접 조회해 확인한 뒤) 검사를 고치고 계속하고 보고에 적는다. 만드는 규칙이 원인이면 고치지 말고 멈춰서 자리(좌표)와 수를 보고한다. 「같은 구간 안 차로 가운데선끼리 만나는 쌍」이 2·3 뒤에도 남으면 멈춘다.

## 하지 않는 것

- 위 「바꿀 것」의 파일과 `public/data/v2/` 의 네 자료 말고는 만들거나 고치지 않는다. `src/`, `test/`, `tools/v2/split.py`·`marks.py`·`check_marks.py`, 옛 도로 코드와 옛 자료를 고치지 않는다.
- 고가·다리, 도로 부지가 없는 큰길(성산로)을 채우거나 고치지 않는다.
- 6절의 값과 1~3단계의 규칙을 바꾸지 않는다. 결과가 어색한 곳은 자리(좌표)를 보고에 적는다.
- `tools/raw/`, `tmp/` 를 커밋하지 않는다. 굽기(`pnpm bake`), 전체 `pnpm test`, 하위 에이전트를 쓰지 않는다.

## 끝나는 조건과 보고

- 굽기 넷과 검사 넷이 끝나고(FAIL 0), 그림과 3D 화면 넷이 생겼고 `pnpm build` 가 끝나면, 바꾼 `tools/v2/` 파일과 `public/data/v2/` 의 네 자료만 커밋하고 푸시한다. 커밋 직전에 `pnpm test:map` 을 한 번 돌리고 요약 줄만 읽는다(이 변경과 상관없이 이미 있던 실패는 개수를 적는다). 커밋 전 `git log --oneline -1` 로 WIP 스냅샷 커밋이 끼었는지 본다. `git stash`·`reset --hard`·브랜치 전환·force push 금지. 커밋은 다른 명령과 붙이지 말고 따로 짧게 실행한다.
- 보고는 열 줄 안쪽, 맨 앞에 커밋 해시: 굽기마다 걸린 시간과 찍힌 수(위 표와 견줘), 검사 결과, 2·3 으로 뺀 단면·묶음의 수와 자리, 자료 네 파일의 크기, 3D 화면의 오류 수, 눈에 띈 것.
- 같은 문제를 두 번 고쳐도 안 되면 멈추고 원인을 보고한다.
