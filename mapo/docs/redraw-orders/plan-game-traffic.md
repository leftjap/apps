## 3. 왜 지금까지 꽉 차지 않았나 (진단)
1. **차가 다닐 수 있는 차로가 적다.** 옛 방식은 정밀도로지도 A2 의 「이어짐」을 그대로 믿는다. A2 는 차로 선의 모양은 정확하지만 이어짐이 끊긴 곳이 많아, 끝까지 이어지는 차로만 쓰면 합정 2+2, 동교 3+3, 신촌 3+2 차로만 남는다(C27). 실제는 편도 4~5차로다.
2. **옛 엔진(`src/sim/cars.ts`, 2,400줄)은 차로 바꾸기가 없고**, 가장자리 출입 자리에서만 차를 넣고 빼며, 횡단 판정·게이트 같은 예전 규칙이 새 차로와 만나면 이유 없는 정체를 만든다(c4 겹침 57,324프레임, c7~c10 정체 334~374대, C30 293초 정체).
3. 이틀 동안 두 마스터가 「옛 엔진 + A2 이어짐」을 고쳐 가며 밀도를 올리려다 같은 벽에 여러 번 막혔다(K1b, K2b, c4, c7~c10, C21, C25, C30). **이 방식이 틀렸다는 신호로 본다.** 더 덧대지 않는다.

## 4. 방식: 모양은 측량에서, 이어짐과 움직임은 게임 규칙으로
- **차로 모형(새로 만든다)**: 길을 교차점에서 교차점까지의 「구간」으로 나눈다(수치지형도 도로 중심선의 끝점 공유. c1-probe: 끝점 97.2% 가 0.1m 안에서 만남. 끝점 없이 엇갈리는 37곳은 입체교차로 보고 잇지 않는다). 구간 안의 차로는 나란한 줄 묶음이다. 줄의 모양은 A2 선이 있으면 A2 선(칠해진 차로 한가운데), 없으면 중심선에서 차로수만큼 띄운 줄(s1-fill-lanes 가 그린 차선과 같은 규칙). **A2 의 이어짐 정보는 쓰지 않는다.** 이어짐은 규칙으로 만든다: 같은 구간의 이웃 차로끼리는 차로를 바꿀 수 있고, 교차점에서는 들어오는 차로 끝과 나가는 차로 시작을 곡선으로 잇는다(좌회전은 안쪽 줄, 우회전은 바깥 줄). 차로가 중간에 끝나면 옆 차로로 합류한다.
- **교통 엔진(새로 만든다, `src/traffic2/`, 옛 엔진과 코드를 공유하지 않는다)**: 차는 앞차와의 거리로만 가속·감속한다(앞이 비면 간다, 막히면 선다. 정지 간격 2m 안팎). 신호는 겹치는 움직임이 없게 만든다: 1판은 「접근로 하나씩 차례로 초록(동시신호) + 보행 전용 시간」. 교차점에는 나갈 차로에 차 한 대가 다 들어갈 자리가 있을 때만 들어간다(꼬리물기 없음). 신호 없는 교차점은 큰길 우선과 한 번에 한 흐름. 0초에 모든 차로를 채워 놓고 시작한다. 지도 가장자리에서 넣고 빼며, 안에서는 차가 계속 돈다.
- **화면**: 정적 지도는 지금 전역 칸 지도(`mapo-all` 칸)를 그대로 바탕으로 쓰고, 새 교통은 새 주소(`traffic.html`)에만 얹는다. 차 모형·색은 지금 것(`makeCarMeshes`)을 쓴다.
- **사람(차가 끝난 뒤)**: 같은 원리. 인도 면에서 걷는 줄을 만들고(폭에 따라 여러 줄), 횡단보도는 보행 신호에만 건넌다. 생기고 사라지는 자리는 역 출구·정류장·화면 밖. 인도가 없는 골목과 보행 거리(걷고싶은거리, 레드로드)는 길 가장자리 띠와 차 없는 거리 면을 따로 만든 뒤 넣는다. 찻길 한가운데로는 걷지 않는다.
- **옛 것과의 관계**: 구역 넷과 `yanghwa-map`·`hongdae-district` 의 옛 차·사람, Codex 의 실험은 그대로 둔다(대조 기준). c1~c3·c6 의 도구(`probe_centerline.py`, `centerline_lanes.py`, `centerline_graph.py`)는 참고하고 맞는 부분만 가져온다.

## 6. 단계 (단계 끝마다 지오에게 완전한 주소의 링크 하나)
- **T0 엔진 핵심(지도 없이)**: 시험용 가상 길(네거리 3차로, 차로 줄어드는 합류, 신호 없는 세거리)에서 5절의 검사 도구와 시험을 먼저 쓰고 엔진을 만든다.
- **T1 차로 모형 표본**: 동교동삼거리 둘레 400m. 차로 줄과 회전 곡선을 정적 지도 위에 겹친 그림으로 검수(칠해진 차선 안에 드는가, 빠진 차로가 없는가).
- **T2 표본에서 달리기** → **링크 1**: 동교동삼거리, 모든 차로가 찬 화면.
- **T3 합정–홍대입구–동교–신촌 큰길과 그 교차 도로** → **링크 2**. 중앙버스차로에는 버스.
- **T4 홍대·신촌 일대 모든 길(골목은 드문드문)** , 부담 측정 → **링크 3**.
- **P1~P3 사람**: 홍대입구역 둘레 표본 → 큰길 인도·횡단보도·역 출구 → 보행 거리와 골목 → **링크 4**.
- **W 마포 전역**: 카메라 둘레만 자세히 계산. 다리·고가 높이(정적 지도 쪽 작업)가 먼저 필요하다.
- **정적 지도(따로, main 에서)**: S-a s1-paint 후보를 검수해 받아들이기 → S-b 큰 교차로 20곳을 사진·모형·겹친 그림으로 검수하고 틀린 것을 규칙으로 고치기 → S-c 다리·고가 높이.
「틀렸다는 신호」: T0 의 검사가 가상 길에서 두 회차 안에 0 이 안 된다. T2 에서 차로 모형 탓의 결함(차선 밖, 빠진 차로)이 표본 차로의 5% 를 넘는다. T3 에서 틱이나 프레임이 문턱의 두 배를 넘는다. 나오면 멈추고 마스터가 원인을 보고 방식을 바꾼다.
