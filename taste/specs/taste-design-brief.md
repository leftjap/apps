# taste — 디자인 의뢰서 v3 (Claude Design 입력용)

> **이 문서의 철학:** 여기엔 **무엇을·왜**가 있다. **어떻게**(레이아웃·비주얼 위계·컴포넌트 생김새·타이포 스케일·그리드·인터랙션 표현)는 **너의 디자인**이다. 받아쓰지 말고, 디자인해 달라.
> 기능·데이터 설계는 `taste-app-spec.md`(디자인 확정 후 갱신). 이전 명세형 브리프(v2)는 이 v3로 대체됨 — git 이력에 보존.

## 0. 한 문장

taste — 내가 별점 평가한 영화·책에서 출발해, Claude가 "다음에 볼/읽을 것"을 이유와 함께 추천하는 개인용 PWA. 부부가 각자 자기 계정으로 자기 추천을 받는다(데이터 개인 격리). 데스크톱 주력 + 모바일 대응.

## 1. 사용자는 단 두 가지만 한다

- **소비** — 추천을 받아, 그 작품의 정보를 본다.
- **평가** — 본 작품을 검색해 별점을 매긴다.

이 둘이 순환한다(평가 → 추천 → 소비 → 평가). 가져오기·로그인은 부수.

## 2. 꼭 담길 구조 의도 (개념만 — 형태는 네가)

- **검색은 1급 시민.** 평가의 입구라, 늘 손 닿는 곳에 있어야 한다.
- **작품 상세 = 허브.** 작품을 열면: 핵심 정보(영화 → 주요 출연진·감독·극본·줄거리 / 책 → 저자·요약) + 별점 + **"이 작품과 통하는 다른 작품 추천 브랜치"**. 브랜치를 눌러 다음 작품으로 **가지치며 탐색**한다.
- **추천은 두 층위.** 작품 상세의 **브랜치**(이 한 작품에서 뻗음) + 홈의 **메인 추천**(평가한 작품 전부를 취합).

이 셋은 *구조 의도*다. "포스터를 어디 둘지, 그리드를 몇 칼럼으로 할지"는 너의 판단이다.

## 3. 단단한 제약 (반드시 지킬 것 — 여긴 재량 없음)

- **별점 0.5단위**, 최저 **0.5★ = "비추"**가 시각적으로 분명해야 한다(이 앱 정체성).
- **외부 링크 없음** — 왓챠/알라딘으로 내보내지 않는다. 모든 정보를 taste 안에서 소비.
- **AI 콘텐츠(브랜치·메인 재생성)는 평가 후 잠시 뒤 도착**(즉시 아님) — "분석 중 → 곧 도착" 상태가 자연스럽게 보여야.
- **4앱(study/gym/today/book)과 한 가족.** 첨부 CSS를 흡수해 그 톤을 그대로. 웜그레이 + 코랄 점 액센트의 절제. 그라디언트 배경·과한 색·화려함 금지.

## 4. 무드

차분한 서재에서 다음 작품을 고르고, 한 작품에서 다음 작품으로 **가지를 타는** 느낌. 포스터·표지는 색을 더하되 화면을 점령하지 않는다. 줄거리·추천 이유 같은 **읽는 본문은 묵직하게**(명조 계열도 좋음).

## 5. 콘텐츠 맥락

- **추천 "이유"가 주인공** — 짧아도 사람이 쓴 듯 따뜻하게. 포스터보다 이유 텍스트가 읽혀야.
- **진짜 한국어 작품으로 채울 것**(로렘 금지). 예: 영화 «헤어질 결심», 책 «사피엔스».
- 메타는 외부 API에서 온다(영화 TMDB / 책 알라딘 — 책 요약·저자는 실호출로 제공 확인). *시안에선 더미로 채워도 됨.*

## 6. 너에게 부탁하는 작업 방식 ★

**구현하기 전에, 3~4개의 뚜렷이 다른 방향을 먼저 말로 제안해 줘.** 각 방향마다:
- 홈과 작품 상세를 어떻게 배치·구성할지(한두 문장)
- 비주얼 톤의 성격 + 한 줄 근거

내가 하나를 고르면 **그 방향만** 구현해 줘. 그려야 할 화면 우선순위는 **작품 상세(허브) → 홈 → (부수)**.

## 7. 시안에서 뺄 것

외부 OTT/구매 링크, 예상 별점 수치, 통계 대시보드, 부부 취향 비교, 추천 dismiss, 설정 화면. 핵심은 **홈 + 작품 상세** 두 화면.

## 8. 첨부 (디자인 시스템 흡수용)

`~/apps/DESIGN.md` · `~/apps/book/src/styles/book.css` · `~/apps/study/src/styles/session.css`.
→ 색·폰트·그림자 같은 **토큰은 여기서 흡수**해라. 이 의뢰서엔 일부러 토큰 수치를 안 박았다(첨부가 정본).
