## B-통합. 표지 축소 — B-1 · B-2 · B-3 · B-4 를 한 줄로

네 항목의 원인이 같으므로 답도 하나입니다.

### 결정: `RTBook3D` 내부를 수정하지 않고, **뷰 전체를 등비 축소**한다

```swift
// 두 경로(Screen02Home.demoStage · RTHomeCarousel.cardView) 동일
RTBook3D(front: …, spineTitle: …)
    .scaleEffect(122.0 / 172.0, anchor: .center)     // = 0.70930
    .frame(width: 140, height: 190)                  // 레이아웃 박스만 축소 (198×268 × 0.7093)
```

**이 한 줄이 네 질의를 동시에 해소합니다.**

| 질의 | 해소 방식 |
|---|---|
| **B-1** 각도·perspective | `RTBook3D.baseRy=9 / baseRx=5 / p=1000` **그대로.** → **(가) 확정.** 책등이 왼쪽에 남고 광원 방향 유지. 문서의 `-15°/2°/800` 은 HTML 시안의 평면 근사값이며 **앱 정본이 아님** — v3 에서 삭제했습니다. 제 문장의 의도는 문장 뒷부분("**크기만 변경**")이 맞습니다 |
| **B-2** 그림자 방향 충돌 | 새 `box-shadow` **미적용.** 내부 `.shadow(0x2E2110@0.28, r:16, x:-6, y:18)` 유지 → `RTBook3D.swift:212` 손대지 않음. `scaleEffect` 가 그림자까지 함께 축소하므로(radius 16→11.3, x −6→−4.3, y 18→12.8) 작은 책에 맞는 그림자가 자동으로 나옵니다 |
| **B-3** `rtBoxShadow` 도형 불성립 | 해당 지시 **폐기.** 컨테이너 사각형 그림자·`destinationOut` 컷아웃 문제 전부 소멸 |
| **B-4** 두께·컨테이너·데모 앞면 | `static let` **전부 그대로.** `D`·`cw`·`ch` 미수정, `HomeBook3DFront` 미수정. 축소는 바깥에서 한 번만 |

**`static let` 을 고치는 대신 `scaleEffect` 를 택한 이유** (귀하의 B-4 제안과의 차이):

`W/H/D/cw/ch` 만 줄이면 **비례하지 않는 절대값이 그대로 남습니다** — 책등 세로쓰기 `.sans(9, 900)`
(`RTBook3D.swift:203`), 종이결 3px 주기, 내부 프레임 inset 8, 책배 3px, 책등 음영 6px,
`lerpQuadV` 의 26pt 밴드(비율이라 안전하나 선 두께 1.2 는 절대값), `rtBookFloatY` 진폭 3.5.
이것들을 개별 보정하면 손댈 곳이 10곳 넘고 6면 투영 회귀 위험이 생깁니다. `scaleEffect` 는 전부 함께 줄입니다.

귀하가 계산한 배율 `122/172 = 0.7093` 과 `252 × 0.7093 = 178.7 ≈ 179` 는 정확합니다 — **등비 축소가 제 의도**입니다.

**단 하나 유의**: `.frame(width: 140, height: 190)` 은 `scaleEffect` **뒤에** 와야 합니다
(`scaleEffect` 는 레이아웃 크기를 바꾸지 않아 그대로 두면 198×268 을 계속 차지합니다).
그림자·투영이 프레임 밖으로 나가는 것은 의도된 동작이니 `.clipped()` 를 붙이지 마십시오.

### 접지 그림자 (`floorShadow`) — 이건 별개 뷰라 수치를 직접 줍니다

`RTBook3D` 의 형제 뷰이므로 `scaleEffect` 가 닿지 않습니다. **같은 배율 0.7093 로 직접 축소**:

| 값 | 기존 | 신규 |
|---|---|---|
| `frame(width:)` | 176 | **125** |
| `frame(height:)` | 26 | **18** |
| `endRadius:` | 88 | **62** |
| `.blur(radius:)` | 8 | **6** |
| `.padding(.top, …)` | 2 | **2 (유지 — C-1)** |

부유 위상 동기 공식(`rtBookFloatY`, `sc = 1 − floatY*0.01`, `opacity = 0.5 − floatY*0.008`)은 그대로.

제가 기록 화면에서 본 패턴을 앱 전체 규칙으로 일반화했습니다.

**정정된 지시** (v3 §8-2):
1. 신규 블록(② ③ ④ ⑤ + 히어로 제목·배지행)에만 `.rtLB(…)` 적용 — 높이를 예산해야 하는 복합 블록.
2. **기존 행(① CTA · ⑥ 마지막 기록 · ⑦ 파트너)에는 추가하지 말 것.** 픽셀 검증을 통과한 행이고, 도입하면
   행높이가 바뀌어 이득 없이 회귀만 납니다.
3. 한 카드에 두 방식이 섞이는 것은 의도된 것입니다.

### H-2. 그 결과 §2 의 카드 420 도 무효입니다

420 을 만든 ⑥⑦ 행 계산(`1 + 9 + 30 + 9 = 49`)에 오류가 두 개 더 있었습니다.

- **높이를 더하지 않는 `overlay` hairline 을 1pt 로 셌습니다.** 두 행의 구분선은
  `.overlay(alignment: .top) { Rectangle().frame(height: 1) }` 이라 레이아웃 높이에 기여하지 않습니다.
- **내용 높이를 아이콘 타일 30pt 로 잡았는데 텍스트 열이 더 큽니다.** 마지막 기록 행의 텍스트 열은
  `sans(11,600)` + spacing 1 + `sans(13,700)`, 파트너 행은 3줄 구조라 30pt 를 넘습니다.
  그리고 H-1 때문에 이 행들은 rtLB 를 쓰지 않아 **토큰으로 예산할 수도 없습니다.**

**정정된 지시** (v3 §2): 카드 상수를 폐기하고 이렇게 씁니다.
- 계산되는 것 = **신규 블록 222** (②40 + ③64 + ④27 + ⑤91)
- 기존 부분은 **변화분만** — 카드 상단 패딩 −2 / 보조 안내 삭제 −(12+행높이) / ⑥ −4 / ⑦ −4
- 절대값은 **빌드 후 실측**. AC #4 는 "스크롤·압축 없음"으로 검증.

귀하가 C-4 에서 "§2 의 434 를 역산하면 27 쪽이 근접" 이라고 쓴 것은 제 어림값을 신뢰한 계산이었습니다.
그 근거가 사라졌으니 C-4 는 **행 높이 27 + 하향 확장 9 = 36pt** 라는 결론만 유효합니다(결론은 유지).

### H-3. 배경 3레이어를 재조정해야 합니다 — v1 이 "유지"라고 한 것이 오류

표지가 29% 작아지고 카드가 222pt 커지면 **책의 수직 중심이 현재보다 약 90pt 위로 이동**합니다.
그런데 독서등 좌표는 하드코드입니다:

- `lightPool` — `.position(x: 195, y: 300)` (`Screen02Home.swift:132`)
- `vignette` — `center: UnitPoint(x: 0.5, y: 0.38)` ≈ y 321 (`:141`)

그대로 두면 **책이 빛 웅덩이 위쪽에 서서 조명이 책 아래에 남습니다.** 이 화면의 컨셉("저녁 독서등 아래
놓인 실물 책")이 깨지는 수준입니다. v3 는 둘 다 새 책 중심으로 올리도록 고쳤고(대략 `lightPool y ≈ 185`,
`vignette y ≈ 0.24`), 정확한 값은 카드 실측 후 산출로 남겼습니다. AC #5 로 추가했습니다.

### H-4. AC #2 가 검증 불가능한 문장이었습니다

> v1 AC #2: "표지가 122×179로 렌더된다(3D 변형 후 실측 ±3pt)."

`RTBook3D` 는 6면을 `p = 1000` 원근 투영하므로 **투영 후 앞면 실측값은 122×179 가 아닙니다**
(`ry = 9°` 단축 + 원근 보정). 이 AC 는 통과할 수 없습니다.
→ v3 는 **검증 대상을 배율(0.7093)과 프레임(140×190)** 으로 바꿨습니다.

### H-5. 진입 애니메이션 3종이 삭제 목록에 없는데 사라질 위험

`demoStage` 를 다시 쓰면 조용히 빠집니다: `rtBookDropIn`(표지), `rtRiseIn`(배지행 delay .04 /
제목 .18 / 카드 .26), `rtPop`(체인 도트 — 이건 체인과 함께 삭제되는 게 맞음).
v3 AC #6 으로 명시했습니다.

### H-6. §2 헤더 라벨 정정 (숫자는 우연히 동일)

v1 은 "상태바 47 + 헤더 39" 로 적었는데, 실제로는 헤더가 `padding(top: 52)` + 아바타 34 = **86** 을
