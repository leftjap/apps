# 소연 아이폰 — 신한 카드 SMS 자동화 추가 (5분)

> 목적: 소연 신한 카드 결제 SMS가 today 가계부에 자동 등록되도록.
> 기존 "Today 가계부 SMS" 단축어를 그대로 사용 — 단축어 신규 작성 불필요. 자동화(트리거) 1개 추가만.

## ⭐ v4 보강 (2026-06-11 — 지오 폰 키워드 전환 실증에서 얻은 학습)

지오 폰에서 키워드 자동화(`1337`/`KB국민카드`)가 e2e 완주 실증됨 → 아래 v3 키워드 "신한" 권장이 강화됨. 셋업 시 추가 주의 2가지:

1. **신규 자동화는 생성 직후 침묵할 수 있다** (지오 폰: 생성 후 테스트 3회 침묵 → ~20분 뒤 정상 발화. 원인 미확정 — 활성화 지연 vs 단축어 폴백 변경, 변수 동시 변경으로 구분 불가). **만들고 나서 "신한" 포함 메시지 셀프 발송으로 발화 확인** 후 종료할 것. 단 셀프 iMessage는 불완전한 대용물 — 침묵해도 실 SMS에선 될 수 있으니 실결제 1건까지 실패 판정 보류.
2. **단축어 "입력 받기 > 입력 없는 경우"를 "계속하기"로 변경** (소연 폰은 현재 "텍스트 요청" — 백그라운드에서 입력이 비면 프롬프트를 못 띄워 흔적 없이 정지). "계속하기"면 빈 입력이 서버 400 `Missing text`로 찍혀 원격 진단 가능. 지오 폰은 2026-06-11 적용 완료.

서버 측 발화 추적(토큰 last_used_at·gateway 로그)은 [`sms-ingest-pipeline.md`](sms-ingest-pipeline.md) "빠른 진단 플로우" 참조.

**✅ 설치 완료 (2026-06-11 21:08)**: 키워드 "신한" 자동화 설치 + e2e 테스트 통과 (발화 + 본문 전달 + gateway 200 + reject 정상, 첫 시도 성공). 자동화 구성은 키워드 2종(신한/현대백화점카드)으로 정리, 구 발신번호·"승인"·본인번호 자동화 삭제. 남은 것: ① 실 신한 결제 1건 확증 ② 단축어 "계속하기" 폴백 변경 여부 확인.

**현황 (2026-06-11 실측)**: 현대 실시간 정상 (6/7까지 연속, 토큰 last_used 6/10 21:22 KST). 신한 자동수집 16~17일째 0건이며, **소연이 5/25 이후 신한 13건을 전부 수동 입력으로 버티는 중** — 키워드 자동화 추가가 이 수작업을 끝낸다.

## ⭐ v3 권장 (2026-06-02 실측) — 신한은 키워드 "신한"으로

**DB 실측 (소연 owner, count=exact):** 신한 거래 **1,250건**(Air 446 + 체크 804) 중 결제 직후 **실시간 자동 ingest = 0건**. DB의 신한 "자동" 5건은 전부 2026-05-26 수동 backfill(같은 초에 일괄 INSERT)이고, 실시간 트리거로 들어온 건 없다. 현대백화점카드는 같은 기간 **6/1까지 실시간 정상**(토큰 last_used 6/1 09:22 = 현대 ingest 시각).

→ **v2의 "발신번호 우월" 권장을 신한에 한해 정정.** 발신번호 방식은 *발신처를 정확히 알 때만* 우월하다 — 지오 삼성(1588-8900)은 발신번호 자동화로 실시간 도달이 확인된다(방식 자체는 정상). 그러나 **신한 발신처 1544-7200은 소연 폰에서 미작동**(이 번호로 잡힌 신한 0건). 자동화 미설정 / 발신번호 불일치 / 비활성 셋 중 하나이며 **폰 점검 전엔 확정 불가**.

**신한 권장 = 키워드 "신한" 자동화.** 근거:
- 신한 SMS 두 포맷 모두 본문에 "신한" 포함 (`신한카드(8244)승인…`, `[신한체크승인]…`) — 실 DB 본문 확인
- 발신처를 몰라도 본문만 맞으면 매칭 → 발신번호 불일치 가능성 우회
- 비결제 신한 SMS가 키워드에 걸려도 파서 **2중 필터**로 차단: reject 룰 8종(거절·취소·문자명세서·0원외화·광고·안내]·차단·비번변경·카드발급) + 결제 시그니처 필수(`hasPaymentSig` — 시간패턴/누적 없으면 null) → 실질 무해
- 현대가 키워드 "현대백화점카드"로 안정 작동 중 = 동일 메커니즘
- **keep(이전 앱)이 이미 그렇게 작동했다**: keep은 발신번호 없이 본문만으로 신한 자동수집(3/16~5/2, 34건 — keep GAS `doPost`가 본문 `smsText`만 받고 카드식별, 발신번호 미사용). today edge도 동일하게 본문 기반 → **발신번호는 원래 불필요**. today 전환 때 발신번호 자동화로 바꾼 게 신한 끊김 원인. (2026-06-03 keep 데이터·코드 분석 + 화면검증 확정)

**선행 순서:** 폰 자동화 탭에서 ① 신한 자동화 존재 여부 ② 있으면 발신번호부터 확인. 없으면 아래 키워드 자동화 신규 추가.

### 키워드 "신한" 자동화 셋업 (소연 폰, ~3분)
1. 단축어 앱 > **자동화** 탭 > **+** > 새로운 자동화 > **메시지**
2. 트리거: **메시지에 다음이 포함됨** → `신한` 입력. (발신자는 비워둠)
3. 하단 **즉시 실행** 켬
4. 다음 > 동작: **단축어 실행** → `Today 가계부 SMS` (입력 = "단축어 입력" 매직 변수)
5. 완료

검증은 아래 검증 A(단축어 ▶ 수동 실행) + 검증 C(진짜 신한 결제 1건) 동일.

> 8619(체크 추정)는 today에 실 SMS가 한 번도 수집된 적 없음(DB 0건, keep/spec 기록만) — 8244·8579만 실 본문 확인됨. 키워드 "신한"이면 8619 본문에도 "신한"이 있는 한 자동 포함된다.

## ⭐ v2 권장 (2026-05-26 후속 진단) — 자동화 1개로 통합

기존 자동화 4개 분석 결과 (DB 증거 기반):
- **#1 발신번호 (삼성 + 본인 +821097761949)**: 본인 번호 트리거가 메모/대화 잡아 잡문자 unparsed 행 누적 (5/16·5/21 3건). 삼성 SMS는 0건 캡처. → **broad/misaligned**
- **#2 키워드 "현대백화점카드"**: 작동 (5/24 2건). 단 발신번호(1588-3650) 알면 더 정확
- **#3 키워드 "승인"**: 전 기간 카드 SMS 0건 캡처. **폰에 없거나 비활성 가설** (폰 직접 점검 필요)
- **#4 발신번호 1544-7200 + 1588-3650** (본 세션 추가): 미검증

**권장 액션**: 4개 → **1개로 통합**. 발신번호 기반이 키워드보다 신뢰성 높음 (광고/잡문자 위험 없음, OR 매치라 한 자동화에 다 들어감).

> ⚠ **2026-06-02 정정**: "발신번호 우월"은 *발신처가 확정된 카드*(삼성 1588-8900·02-2000-8100, 현대 1588-3650)에만 유효. **신한은 예외** — 1544-7200으로 잡힌 SMS가 실측 0건이라 발신처 미확정. 신한은 위 v3의 **키워드 "신한"** 방식 권장.

### 통합 자동화 셋업 단계 (소연 폰)

1. **단축어 앱 > 자동화 탭**
2. 기존 자동화 정리:
   - **#1 (발신번호 삼성+본인)** → "+821097761949 (소연 본인)" 만 빼고 나머지 유지 (또는 통째로 삭제 후 새로 만들기)
   - **#2 (키워드 현대백화점카드)** → 통합 자동화로 대체되니 삭제
   - **#3 (키워드 승인)** → 작동 0건이라 **삭제**
3. **통합 자동화 1개 신규** (또는 #4 확장):
   - 트리거: **발신자** 선택 → **특정 발신자**:
     - `+8215447200` (신한카드)
     - `+8215883650` (현대백화점카드)
     - `+8215888900` (삼성카드)
     - `+82220008100` (삼성카드 해외)
   - 메시지 키워드: **비워둠** (발신번호 OR 매치만 사용)
   - **즉시 실행** 켬
   - 동작: **단축어 실행** → `Today 가계부 SMS`
4. **삼성 카톡 ingest는 별도 처리** (사용자 명시) — 본 자동화 대상 아님

### 통합 후 검증
- 단축어 ▶ 수동 실행으로 단축어 본체 흐름 확인 (검증 A)
- 진짜 카드 결제 1건 발생 시 자동 캡처 확인 (검증 C)
- (검증 B = 본인 번호 트리거 제거됐으니 더 이상 해당 없음)

## ⚠ 사전 — 단축어 앱 오프로드 방지 (2026-05-26 발견된 핵심 함정)

iOS의 **"사용하지 않는 앱 정리"(Offload Unused Apps)** 가 단축어 앱을 자동 제거하면 **모든 자동화가 조용히 정지**합니다 (소연 폰 실 사례 — 05-14 이후 ingest 정지의 진짜 원인 후보).

**필수 셋업:**
1. 폰 `설정 > App Store > 사용하지 않는 앱 정리` → **끔**
2. 단축어 앱이 홈화면에 보이는지 확인 (없으면 App Store에서 "단축어" 검색해 재설치)
3. 재설치 시 기존 단축어·자동화는 데이터로 보존되지만 일부는 **재활성화** 필요 — `자동화` 탭에서 각 항목 토글 상태 확인

## 사전 확인

소연 폰 Shortcuts(단축어) 앱에:
- **단축어** 탭 → "Today 가계부 SMS" 단축어 존재 (현대백화점카드 SMS가 가계부에 자동 등록되고 있으면 OK)
- **자동화** 탭 → 기존 자동화 3개 (발신번호 / 키워드 "현대백화점카드" / 키워드 "승인") 중 일부 또는 전부 존재

신규 추가할 자동화는 위 단축어를 호출하는 **4번째 자동화**.

> 카드별 발신번호 매핑은 [`specs/sms-ingest-pipeline.md`](../specs/sms-ingest-pipeline.md) "카드·발신번호 마스터" 섹션 참조. 본 문서는 폰 셋업 절차만.

## 단계 (iOS 18 기준, 17·16도 거의 동일)

1. **단축어(Shortcuts) 앱** 열기 → 하단 **자동화** 탭
2. 우상단 **+** 버튼 → **새로운 자동화**
3. **메시지** 선택
4. 트리거 설정:
   - **발신자**: **특정 발신자** 선택 → **연락처 또는 번호 추가**:
     - `+8215447200` (1544-7200, 신한카드) — ⚠ 실측 0건. v3 권장은 키워드 "신한". 발신번호로 쓰려면 폰에서 실제 신한 발신처부터 확인
     - `+8215883650` (1588-3650, 현대백화점카드) — 같은 자동화로 같이 잡으면 키워드 자동화 #2 의존 줄어 안정적
   - **메시지에 다음이 포함됨**: **비워둠**
   - 하단 **즉시 실행** 켬 (확인 없이 자동) ← **중요**
   - **알리기** 끔 (선택 — 알림 시끄러우면)
5. **다음** → 동작 추가:
   - 검색창에 **단축어 실행** 입력 → **단축어 실행** 액션 추가
   - 액션의 "단축어" 자리 → **Today 가계부 SMS** 선택
   - 액션의 "입력" 자리 → **단축어 입력** 매직 변수 자동 들어와 있어야 함. 안 들어와 있으면 매직 변수 메뉴에서 **셸 입력**/**메시지**/**텍스트** 중 SMS 본문에 해당하는 것 선택 (기본은 "셸 입력")
6. 우상단 **완료** → 저장

## 검증 — 무엇을 검증할 수 있고 무엇은 못 하는지 정확히

자동화는 **트리거 조건마다 검증 방법이 다름.** 본인이 본인에게 SMS 보내봐도 #4 발신번호 자동화는 트리거 안 됨 (발신번호가 본인 번호이지 1544-7200이 아니므로).

### 검증 A. 단축어 본체 흐름 (입력 → POST → DB → PWA)
**방법**: Shortcuts 앱 → 단축어 탭 → "Today 가계부 SMS" → 우상단 ▶(재생) 버튼 → 입력 prompt에 아래 텍스트 붙여넣고 실행:
```
[Web발신]
[신한체크승인] 김*연(8579) 05/26 19:30 (금액)1,000원 단축어수동테스트
```
1분 내 today 가계부 RECENTS 최상단에 "단축어수동테스트 / 1,000원 / K-패스 신한카드 체크" 뜨면 단축어 본체 + edge function + DB + PWA 흐름 모두 정상. (자동화 트리거와 무관하게 단축어 자체 검증)

### 검증 B. 자동화 #1 (본인 번호) 트리거
**방법**: 소연이 본인 번호로 SMS 발송 (위 텍스트 사용):
```
[Web발신]
[신한체크승인] 김*연(8579) 05/26 19:30 (금액)1,000원 본인발송테스트
```
수신 1분 내 가계부 등록되면 #1(본인 발신번호) 자동화 → 단축어 호출 흐름 정상. **단 이는 #1 검증이지 #4 검증 아님.** spec §138-141의 2026-05-15 검증도 이 방식이었음.

### 검증 C. 자동화 #4 (1544-7200 / 1588-3650 발신번호) 트리거
**방법**: 본인 발송으론 발신번호 매치 안 돼 검증 불가. 두 가지뿐:
1. **진짜 신한카드(또는 현대백화점카드) 결제 1건 발생** — 1~2분 내 가계부 자동 등록되면 #4 정상
2. (대안) 단축어 앱에서 자동화 #4를 long-press → "실행" 옵션이 있으면 그것으로 수동 트리거 (iOS 버전에 따라 메뉴 다름)

검증 A + B 통과 후 #4 자동화의 트리거 조건(발신번호)만 OS 단에서 매치되면 작동이 보장됨 — A·B로 단축어 본체와 자동화→단축어 호출 흐름이 검증됐기 때문. C는 진짜 결제 발생 시 확인이 현실적.

## 트러블슈팅

- **테스트 SMS가 자동화를 트리거 안 함**: iOS는 본인 → 본인 SMS를 메시지로 안 받는 경우 있음 → 다른 사람(지오 등)에게 부탁해서 위 텍스트를 소연에게 보내 받게.
- **자동화가 실행 확인 묻기 팝업 뜸**: 자동화 편집 → **즉시 실행** 토글 확인.
- **단축어 입력이 비어 보냄 → 가계부에 unparsed 행 추가됨**: 매직 변수가 "단축어 입력"이 아닌 다른 걸 가리킴. 단축어 실행 액션의 입력 자리를 길게 눌러 매직 변수 메뉴 → SMS 본문 변수로 재선택.
- **신한 외 다른 메시지도 잡혀버림**: 발신자가 다른데 +8215447200이 잡힘 → 발신자 추가 시 정확 번호 재입력.

## 기존 자동화 3개와의 관계

(spec [`sms-ingest-pipeline.md`](../specs/sms-ingest-pipeline.md) 자동화 트리거 섹션)

| # | 트리거 | 잡는 SMS |
|---|---|---|
| 1 | 발신번호 (1588-8900 / 02-2000-8100 / +821097761949) | 삼성카드 / 삼성 해외 / 소연 본인 |
| 2 | 키워드 "현대백화점카드" | 현대백화점카드 — #4가 발신번호로도 잡으므로 향후 제거 또는 유지 모두 무해 (unique 제약으로 1건만 저장) |
| 3 | 키워드 "승인" | 모든 카드 broad fallback (작동 여부 불확실) |
| **4 (신규/확장)** | **발신번호 +8215447200 + +8215883650** | **신한카드 (체크 8579 / Air 8244) + 현대백화점카드** |

모든 자동화가 **같은 단축어 "Today 가계부 SMS"**를 호출. 단축어 자체는 수정 불필요.

## 셋업 후 사용자(지오)가 할 일

- 소연이 셋업 완료했다고 알리면 본 파일의 검증 1단계(테스트 SMS) 결과 확인.
- 1~2일 운영 후 실제 신한 결제 발생 시 가계부 자동 등록 모니터링.
- 추후 다른 카드(예: 삼성→카톡 이전 후 카톡 ingest) 추가 시 동일 패턴으로 자동화 추가.
